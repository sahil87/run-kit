Operator Console Drawer Studies

Design study for the desktop operator console (the ⌘J quake drawer) — where the compose lives, how the drawer resizes, how many chrome rows it spends, and whether a click below it should close it. Mocks mirror components/operator-console.tsx and components/operator-omnibox.tsx as shipped 2026-09-12; the recorded design decisions live in docs/memory/run-kit/ui/operator-console.md. None of the proposals here break the one-input rule: the compose seam in lib/operator-console.ts stays the single draft/send owner — only where its one view renders moves.

B · Proposal — the compose docks at the drawer's bottom edge

The omnibox stays as the standing affordance at rest (glyph + state dot + chord). When the machine enters open, the top bar's center hands the cell back to the page heading and the same compose seam renders as a docked strip under the terminal — the exact idiom every terminal route already uses. Draft, context chip, error line, send path: unchanged, because they are module state; only the view moves. The eye line becomes prompt → compose → reply, all at the bottom.

C · Resize — every edge, both corners live

Drag the drawer below. Today reproduces the shipped behavior: the tongue drags height, the (invisible) sides drag width symmetrically about the center line. Proposed exposes the full bottom edge, both sides and both bottom corners, tints the grabbed edge accent-green on hover, and lets each edge move only its own side (the drawer may sit off-center; geometry gains a centerOffsetPx). Double-click any grip to reset. The amber ring is your pointer — watch whether the corner follows it.

Zones extend 4–6px outside the border so the grab is forgiving; cursors: ew / ns / nesw / nwse.

Why symmetric fails at a corner: pulling the bottom-right corner 100px right grows the drawer 200px, so the corner runs away from the pointer at twice its speed. Symmetric width was chosen to keep the drawer centered under the top-bar omnibox; once the compose docks inside the drawer that anchor is gone, and the quake-console genre only needs the drawer to open centered, not to stay so. Clamps stay: height 25–85vh, width 420px–96vw, and the offset is clamped so the drawer never leaves the viewport. Persisted key grows from {heightVh, widthPx} to {heightVh, widthPx, centerOffsetPx}; the reader defaults a missing offset to 0, so stored geometry survives.

E · Click-away vs. pin

Today an outside click collapses the drawer. That is right for a peek, wrong for the case the drawer is best at: reading the operator while you type in the pane below it. A pin in the header suspends only the outside-click listener; ⌘J, Esc and ▼ still collapse.

Rejected

  • Keep the compose in the top bar and add a second one in the drawer. Two inputs, two error lines, forked draft — the recorded rejection stands.
  • Drop the compose and type straight into the embedded xterm. Loses IME, paste-of-large-blocks, attachments, and the templated chat lane's context envelope; click-into-terminal already exists as the escape hatch.
  • Symmetric width with corners. The corner cannot follow the pointer (Study C, "Today" mode). Either no corners, or independent edges.
  • Remove click-away entirely. The peek case (⌘J, glance, click elsewhere) is common; the pin keeps both.

[ Review Surface — Comment States ]

Every state a line-anchored comment passes through, in the review tile: the hover affordance, the composer, a single comment, a multi-party thread, and the two kinds of "old" — resolved and outdated. The A / B / C switcher repaints every code line so each state can be read in all three highlighting treatments; § 1 shows the three side by side, because the anchored line is one of only three places in this whole layer where they differ at all.

👀 is the marker — and it is deliberately actor-blind. The same reaction already appears by hand in real threads, and rather than being a collision to engineer around, that is the semantics: 👀 means claimed, by whoever put it there. A human reacting 👀 says "I am handling this" and suppresses dispatch exactly as the agent's own mark does. One signal, two writers, one meaning.

What follows from actor-blindness: the predicate is unresolved && !hasEyes with no identity join, so rk needs no bot account and no GitHub App — it marks as whoever is authenticated. Un-reacting releases the claim and the thread becomes eligible again on the next tick, which doubles as the manual re-dispatch gesture. And because the mark is visible on github.com, the claim is legible to a human reviewer who never opens run-kit.

Dispatch granularity. The chip sits on the thread, not the comment — one thread is one unit of work, and the agent is handed the whole thread (every comment, in order) so it has the argument, not just the last line. 8 · Reading

The comment layer does not move the highlighting decision — it hardens it. Across every state above, the A/B/C choice is visible on exactly three elements: one anchored line per thread, inline chips, and suggestion blocks. Everything that makes this surface useful — the thread, the authorship, the dispatch state — is identical in all three. B remains the recommendation, and A is now a more serious option than it was before this study, not less.

The dedupe marker is settled: 👀, actor-blind (§ 4). It needs no bot identity, it is legible on github.com to someone who never opens run-kit, and un-reacting is the manual re-dispatch gesture. The remaining states that gate dispatch are mechanical and listed in § 6 — outdated never dispatches, resolved is terminal, and a suggestion-only thread is handled by the Apply button rather than an agent turn.

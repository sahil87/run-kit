[ B · ITERATION 2 · CONTAINED SIZE — WHICH WAY DOES A BAND SCROLL? ]

The two growable axes have different growth geometry, so they want different scroll directions. Color is a 2D matrix — families × shades. Families grow, shades are fixed at 2 — so growth is horizontal by construction: a vertical scroll would either hide a shade row (breaking the pairing) or re-wrap families (breaking column identity). Flair is an unordered 1D set shown as a wrap grid — it grows downward naturally, rows stay full, and vertical wheel scroll needs no modifier keys. Marker is a closed 6-state set by design and never scrolls.

Reality check before any scrollbar ships: at the real counts — 10 families (stable), 6 markers, 10 flairs (%550's final number) — nothing needs to scroll. ∅ + 10 flairs = 11 cells = 2 rows of 8. The mocks below inflate the vocabulary (16 families / 24 flairs) to make the mechanics visible; the caps are the growth story, wired only when a band crosses its budget.

B-V · VERTICAL FLAIR CAP (24 FLAIRS) — PARKED
flair capped at 2 rows + a 6px peek of row 3 — the clipped cells advertise the scroll even with hidden scrollbars; edge fade matches the sidebar's scroll-edge pattern; wheel just works; panel height is constant forever
hidden flairs are invisible until scrolled (tolerable: flair is unranked decoration); thin scrollbar steals ~7px of the 8th column
B-H · HORIZONTAL STRIPS (16 FAMILIES / 24 FLAIRS) — CHOSEN
height truly fixed regardless of any axis's growth; color scrolls the way it grows — family columns slide, both shade rows always visible; half-cut column at the right edge is its own affordance; swipe-friendly on coarse pointers
horizontal mouse wheel needs shift/trackpad — second-class on exactly the fine-pointer surfaces this picker lives on; macOS auto-hides scrollbars so overflow is silent without the cut cell; flair as column-flow pairs lose their wrap-grid reading order

Recommendation: per-axis, matching geometry — ship B with no scrollbars today (nothing overflows at real counts), and give each band a cap for the day it's crossed: flair → vertical (2 rows visible + peek + edge fade, activating past 16 cells), color → horizontal (both shade rows fixed, family columns slide — only if the family vocabulary ever grows past 10, which the hue-discrimination design argues against), marker → never. One direction per band, never both; the panel's footprint becomes a constant ~242 × ~230px.

KEYBOARD: ARROW MOVES CALL scrollIntoView({block:"nearest"}) — THE CAP IS INVISIBLE TO THE GRID MODEL · COARSE POINTERS: SAME CAPS, TOUCH SCROLL FREE

DECIDED: B-H. The height-constancy and swipe story won over the wheel-modifier concern; the cut-cell + edge-fade affordance carries the discovery burden. Iteration 3 below refines it.

[ B · ITERATION 3 · B-H REFINED — MARKER GROWTH + THE MOTION SPLIT ]

The channel rule: markers mean something and hold still; flairs mean nothing and move. Markers predate flairs, so motion was the only spice available when they were designed — now it blurs the axis boundary. Under the rule: dashed's data rain migrates to a rain flair (same CSS, now user-composable with ANY marker); dashed keeps its static stripe; double's selection-gated scanline crawl retires (it was feedback, not decoration — if missed it returns as a scan flair). The STATIC row textures (scanlines, hazard wedge) stay marker-paired: they do discrimination work, which is half the mushiness fix.

Why markers felt mushy: five weights of one device (a left stripe) encode phases — an ordinal form for categorical meaning. The eye ranks dotted < thick but can't recall "dashed = working" without a legend. And half the states people reach for are machine-derivable: "agent working" is the status dot's job (@rk_agent_state, Constitution X — derivation wins), and a hand-set copy of it goes stale within minutes, poisoning trust in the whole axis. So the growth rules: (1) new markers add pattern classes, never another weight between two existing ones; (2) the suggested semantics cover only states the human alone knows — discussion pending, I'm done, can be deleted — never agent lifecycle.

[ B · ITERATION 4 · ∅ IN HEADERS · IN-PROGRESS REMAP · SCAN FLAIR ]

Three changes. (1) ∅ moves into each band's header — the header names the axis, the header clears it. Every strip drops a column: at the same 190px, color shows an extra family and the 8-state marker strip stops scrolling entirely (8 × 21px = 165px fits). (2) The in-progress remap. "In progress" is the state that matters most, so it gets the strongest iconic form: hatch — 45° construction-tape diagonals — becomes THE in-progress marker, and the hazard wedge texture migrates to it (it was culturally backwards on completed: hazard stripes mean work zone, not done). thick = completed goes clean and quiet — the most resting state gets the quietest treatment. dashed demotes to a generic mid-weight label; double releases its scanlines to the flair axis and stays a plain twin stripe. Net: markers carry exactly ONE texture pairing (hatch ↔ hazard), which is iconic rather than memorized. (3) scan ships as a flair — scanlines + the crawl + the refresh band, now always-on: as a flair the old selection-gating dissolves, since flair motion is always-on by definition. In-progress is now conveyed redundantly by design: hatch marker (the fact) + optional rain/scan flair (amplification) + the status dot (machine truth) — three channels that agree.

[ B · ITERATION 5 · UNSET EVERYTHING — THE PANEL-LEVEL − ]

One more verb: unset everything. It extends the scope grammar the minus already established — a − clears whatever its row names. A band header's − clears that axis; the panel header row (the preview + ✕) now carries its own −, and its row names the whole label — so it clears color, marker, and flair in one click. Same treatment (secondary → primary hover), same ring rule at its scope: the panel − rings when every axis is unset. Keyboard: the stack's top row becomes two cells, [−] and [✕].

B-H · PANEL − = CLEAR ALL · TRY IT (SET A FEW, THEN THE TOP −)
no new vocabulary — the same verb at a wider scope; one click to a clean row; cheap to undo since selection never dismisses (re-pick immediately); ring = "label fully unset" gives the panel a readable rest state
sits one cell from ✕ — a misclick clears three axes instead of closing (mitigated: gap + hover tip, and the picker stays open so recovery is instant); discoverable only by tooltip/position until used once

Rejected shapes: a "Clear all" text row (heavier chrome, breaks the glyph grammar the headers just established); hanging clear-all on the caption (the caption is STATE, never action); long-press on a band − (invisible, non-obvious, hostile to keyboard).

WRITE SEAM: CLEAR-ALL EMITS THE THREE EXISTING CLEARS (onSelect(null) · onSelectMarker("") · onSelectFlair("")) — NO NEW API; CALLERS WITHOUT A BAND JUST DON'T RECEIVE THAT AXIS

[ STUDY · A THIRD SHADE — {family}-light ]

Proposal: every family gains a light shade — mean-L + 0.14, the mirror of dark's − 0.14, stored orange-light (additive, zero migration, same write seam as dark). The B-H band absorbs it as a one-time third row (+21px; light on top, dark at the bottom — the rows ARE the lightness axis). The question that decides it is not mechanics but row-scale discriminability: rows wear color as a 14%-blend tint + a guarded stripe, which compresses lightness differences. Judge the stacks below — every swatch and row tint is computed by the real pipeline.

[ NAMING · THE PANEL AND ITS AXES ]

The combo already has an incumbent name — Label — carried by the palette action (Window: Label), the aria-label ("Label picker"), the wiki study, and the memory docs. The tension: themes.ts documents flair as "DECORATION ONLY — unlike the marker's label role".

PANEL NAMEFORAGAINST
Label ·incumbent zero churn — palette, aria, tests, wiki, memory all say it; "how this row is labeled" covers color + marker naturally overclaims flair, which is documented as pure decoration
Look honest umbrella (identity + decoration); singular, terminal-y; "Window: Look" scans rename churn across 6+ surfaces; loses the semantic hint that marker states carry conventions (working/completed)
Stylecollides with the theme system and CSS vocabulary
Combo / Looksvague / reads as a menu item, not a noun the docs can own

Recommendation: keep Label as the panel name; spend the effort naming the axes in-panel instead — color · marker · flair, exactly the identifiers the code, backend validators, and tmux options (@rk_color-family / @rk_marker / @rk_flair) already use. If flair's growth makes it feel first-class enough to demand an honest umbrella, Look is the fallback — decide before %550's states ship user-facing copy.

Cross-layer checklist before any of this ships: backend flair closed set + error copy · picker keyboard grid rewrite (GRID_ROWS/MARKER_CELLS 1:1 pairing assertion dies with the column) · swatch-popover unit tests + e2e chrome assertions · flair tooltips need real names at 10 states · coarse-pointer rail-card reuse (width budget) · reduced-motion gate ordering · Window: Label palette copy if the panel is renamed.

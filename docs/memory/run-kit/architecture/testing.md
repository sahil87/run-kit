# run-kit Architecture — Testing

## Testing

Tests whose lifetime is tied to a compatibility shim carry `// retire-with: {shim-name}` immediately above the test, or in the file header when the whole spec is shim-bound. Shim-removal sweeps use `grep -r "retire-with"` to locate the full cross-language set.

The aggregate `just test` recipe delegates to `scripts/test-all.sh`, which runs the three phases by invoking their own recipes (`just test-backend` → `just test-frontend` → `just test-e2e`, preserving per-recipe deps like `_ensure-tmux-conf`), frames each with timestamped append-only banners (`[N/3] <phase> — started HH:MM:SS` / `— ok in XmYYs` / `— FAILED in XmYYs (exit E)`) plus a final per-phase summary (ok / failed / not-run), fails fast with the failing phase's exit code, and tees the whole run to `/tmp/rk-test-<timestamp>.log` (path echoed as the first line, for `tail -f` / capture-pane peeks mid-run). Orchestrator output is append-only by design — no spinners, `\r` rewriting, or cursor control (rewrites garble captured logs and capture-pane peeks). The three sub-recipes and CI (which calls them directly, never `test`) are unaffected (260904-6o28-test-progress-banners).

### Go Unit Tests

Go `testing` package with table-driven tests. Test files co-located with source using `_test.go` suffix. Test scripts: `go test ./...` from `app/backend/`.

**Shared test scaffolding lives in `app/backend/internal/testutil`** (import path `rk/internal/testutil`) — a regular (non-`_test`) package, so its helpers are importable from `_test.go` files in any backend package. It is the first place to look before hand-rolling test scaffolding. Two families:

- **Stub executables** (`stub.go`): `WriteStub(t, dir, name, script)` writes `script` as an 0o755 file into `dir` (`t.Fatalf` on write error). `StubOnPath(t, name, script)` layers on top — fresh `t.TempDir()` + `WriteStub` + a PATH **prepend** that preserves the original (restored by `t.Setenv` cleanup) — and returns the dir. The PATH layer is **opt-in**: callers wanting PATH *replacement* call `WriteStub` and do their own `t.Setenv("PATH", dir)` (`internal/riff`, `internal/wt`); `cmd/rk/upgrade_test.go` wants the prepend and uses `StubOnPath`. Fixed-name conveniences (`stubFab` in riff, `installFakeBrew` in `cmd/rk`) stay **local** thin delegates in their own test files, keeping `testutil` package-agnostic.
- **Deadline-poll waits** (`wait.go`): `WaitUntil(t, timeout, cond) bool` polls `cond` at a fixed 50ms cadence (`waitPollInterval`) until true or `timeout`, checking `cond` **before** the first sleep so an already-true condition returns immediately; `timeout` stays a per-call-site argument (2s/3s in practice). `MustWaitUntil(t, timeout, cond, msg, args...)` is the fail-on-expiry variant. Its `args` evaluate **eagerly at call time**, so a failure message embedding state computed during the wait must use `if !WaitUntil(...) { t.Fatalf(..., freshState) }` instead. Callers: `internal/tmuxctl` (supervisor/client/integration), `api/terminals_relay_test.go`, `api/terminals_ws_test.go`.

Two shapes are deliberately **not** expressible through these helpers and stay bespoke: loops returning a value from inside the body or needing a tighter poll (`internal/tmuxctl/client_test.go`'s `fakeSleep.triggerNext`, 2ms), and blocking frame-readers / fixed-duration drain loops that must not exit early (`api/terminals_relay_test.go` `conn.ReadMessage()` waits, `api/sse_subscriber_test.go` drains). `internal/desktop/installed_test.go`'s `writeFakeBundle` is likewise outside `testutil` — it builds a directory bundle (`MkdirAll` + an 0o644 plist), not a 0o755 executable. `testutil` carries no `_test.go` of its own; every migrated caller exercises it, and it is not linked into the production binary.

Current Go test coverage (`app/backend/`):
- **Internal packages**: `internal/validate` (input validation + tilde expansion + filename sanitization), `internal/config` (env var reading, port validation, defaults), `internal/tmux` (listSessions parsing + byobu filtering, listWindows activity computation), `internal/sessions` (native fab-tier derivation — temp-dir `.fab-status.yaml` symlink + `.status.yaml` fixtures covering the five display-stage tiers, subdirectory walk-up, and per-pane fail-open degradation — plus the change-bound-wins window rollup)
- **CLI command tests**: `cmd/run-kit/root_test.go` (no-args defaults to serve), `cmd/run-kit/version_test.go` (version output format), `cmd/run-kit/doctor_test.go` (LookPath-based dependency check)
- **Handler integration tests**: `api/health_test.go`, `api/sessions_test.go`, `api/windows_test.go`, `api/directories_test.go`, `api/upload_test.go`, `api/sse_test.go`, `api/spa_test.go` — all use `httptest.NewRecorder` with the chi router and mock `SessionFetcher`/`TmuxOps` interfaces for tmux isolation. Cover response shapes, validation errors, URL param parsing, content-type enforcement. `api/terminals_ws.go` (the pane relay mux) (260717-803u-relay-mux) has `api/terminals_ws_test.go`: the HOL scheduler test (`TestScheduler_EchoNotHeadOfLineBlocked` — paced-writer seam, no real network) plus per-stream behavior against a live-tmux `/ws/terminals` dial (`opened` precedes data, initial-size attach + TERM forcing, resize, client-close→`closed` 1000, bad/missing window→`closed` 4004 with the socket still open). The 4001 attach-failure path has no dedicated test (forcing `StartWithSize` to fail needs a seam that does not exist — accepted). `api/terminals_relay_test.go` holds the per-stream relay suite as `/ws/terminals` tests (helpers `withTerminalsTmux`/`terminalsServerWithProdTmux`; the `relay` in the file and helper names refers to the per-stream relay behavior those tests cover, not a live endpoint). The riff/fork handlers inject a dedicated mock `RiffEngine` instead of extending `TmuxOps` (§ Riff Engine Injection): `api/riff_test.go` + `api/fork_test.go` — enumerated in [rk-riff](rk-riff.md) § Tests rather than duplicated here

### Frontend Unit Tests (app/frontend/)

Vitest with jsdom environment. Config at `app/frontend/vitest.config.ts`. MSW mocks all API endpoints (`app/frontend/tests/msw/handlers.ts`). Test files co-located with source using `.test.{ts,tsx}` suffix. `session-context.test.tsx` drives a `MockWebSocket` speaking the state-socket protocol (hello/subscribe/ack/event/gone) (260716-qf3j-state-socket); its behavioral assertions (per-server isolation, server-order re-sort, server-gone teardown, host-metrics dedup, metrics-subscription open/drop on attach, `serversLoaded`, `pendingServer`, `shouldReloadOnVersion`, StrictMode re-subscribe) run end-to-end through the live `useHostMetrics()` seam.

Test coverage includes: sidebar (expand/collapse, window selection, kill session, activity dots, duration display, info popover), breadcrumb dropdowns (open/close, selection), drawer (open via hamburger, close on selection), command palette (Cmd+K), modifier state, touch targets (44px on `coarse`), API client (correct URL construction for each endpoint).

#### Shared test scaffolding — `src/test-utils/`

`app/frontend/src/test-utils/` holds the shared vitest scaffolding, **imported per-test and deliberately NOT registered in `vitest.config.ts` `setupFiles`** — the only auto-installed frontend test code is `src/test-setup.ts`, which carries unconditional environment polyfills (`ResizeObserver`, `document.fonts`) and nothing opt-in. Two modules:

- **`fixtures.ts`** — the canonical spread-override factories `makeWindow(overrides?: Partial<WindowInfo>)`, `makeSession(overrides?: Partial<ProjectSession>)`, and `makeWindowWithPanes(overrides?: Partial<WindowInfo>)` (composed on `makeWindow`), typed against `@/types`. One canonical default set (`windowId: "@0"`, `index: 0`, `name: "zsh"`, `worktreePath: "/home/user"`, `activity: "idle"`, `isActiveWindow: false`, `activityTimestamp: 0`); `makeWindowWithPanes` layers a `/home/user/code/run-kit` worktree plus one active `%5`/`main` pane. Every signature is all-optional — a test that cares about a field (including `windowId`/`index`) passes it as an explicit per-call override rather than getting a bespoke required-args variant.
- **`match-media.ts`** — `stubMatchMedia(predicate?: (query: string) => boolean)` installs the fire-and-forget matchMedia stub via `vi.stubGlobal`, holding the MQL-shaped object literal (`matches: predicate(query)`, `media`, `onchange`, and `vi.fn()` listener stubs) in one place and returning the installed mock for per-test customization. The default predicate is always-false. Because `vi.stubGlobal` defines a configurable property on the jsdom global (jsdom implements no `matchMedia`), a test may `delete window.matchMedia` to restore jsdom's `undefined` — `tip.test.tsx` depends on exactly that restore path in its `afterEach`.

**Two matchMedia families, only one shared.** `stubMatchMedia` serves the *predicate* family — fire-and-forget stubs whose only variable is the per-query `matches` verdict. Tests that drive real media-query behavior (change events, listener bookkeeping) instead build a controllable MQL object and stub via `vi.stubGlobal("matchMedia", vi.fn().mockReturnValue(mql))`; that family (`hooks/use-coarse-pointer.test.ts`, `contexts/theme-context.test.tsx`, `theme-selector.test.tsx`, `swatch-popover.test.tsx`, `terminal-client.test.tsx`, `sidebar/index.core.test.tsx`, `sidebar/index.test.tsx`'s `makeMatchMedia`) is a different shape and stays bespoke. Reach for `stubMatchMedia` only when the test never inspects or fires listeners. Thin per-file wrappers over it (`stubCoarsePointer()`, `stubPointer(coarse)`) are idiomatic — they encode a file's pointer semantics while the shared module owns the literal.

### Playwright E2E Tests (app/frontend/tests/e2e/)

Config at `app/frontend/playwright.config.ts`. Port/socket identity flows from the harness env: `scripts/test-e2e.sh` and `scripts/pw.sh` set `E2E_PORT` to the worktree's derived e2e port (from `scripts/e2e-env.sh` — a deterministic `cksum`-hashed triple in 3400–3699; `RK_E2E_PORT` overrides) and `E2E_TMUX_SERVER`/`E2E_TMUX_FAMILY` to the derived socket family; both scripts still pass `RK_PORT` for non-Playwright readers in the child env, but no Playwright-side code consults it — `E2E_PORT` is set only by the harness, so a direct `playwright test` fails closed on port 3333 (`process.env.E2E_PORT ?? "3333"` in the config), connecting to nothing rather than a live instance (the ambient direnv-exported `RK_PORT` can no longer defeat the fallback). Specs seed real tmux and board state through shared underscore-prefixed helper modules rather than per-file copies.

Describe titles tagged `@perf` form the on-demand performance-audit tier. The config-path `grepInvert` excludes this tier from `just test-e2e` and CI; `scripts/pw.sh` sets `RK_E2E_PERF=1`, so `just pw test <name>` includes it.

Every `test()` in this directory carries a `/** Proves: … Steps: … */` JSDoc block immediately above it — the user-visible behavior under test in one or two sentences plus a numbered step list mirroring the body, so a reviewer can reason about intent without reading Playwright APIs — and each spec file opens with a file-header comment covering shared setup (`beforeAll`/`beforeEach`, fixtures, viewport, `page.route` stubs, saved/restored host-global state). Intent comments state what the test proves and why the setup is shaped as it is; they narrate no history and cite no change IDs or PR numbers. A PR that adds or modifies a `test()` updates its intent comment in the same commit. Unit tests (`*.test.ts`/`*.test.tsx`, `*_test.go`) are exempt — the test name plus code is self-documenting at that scope (constitution § Test Intent Comments).

- **`app/frontend/tests/e2e/_tmux.ts`** — the single tmux fixture. Exports `TMUX_SERVER` (`process.env.E2E_TMUX_SERVER ?? "rk-test-e2e"`) and `TMUX_FAMILY` (`` process.env.E2E_TMUX_FAMILY ?? `${TMUX_SERVER}-` `` — the family anchor, trailing hyphen included, that every secondary name is built from); `global-teardown.ts`, a non-spec Node teardown, keeps its own env reads (family-anchored scan with the same fallbacks), plus `createSession` / `killSession` / `killServer` / `newWindow` / `listWindows` and the low-level `tmux()` runner. `createSession(session, { windows: [{ name, command }] })` creates a detached 80x24 session (best-effort pre-kill, first window via `new-session -n`, the rest via `new-window`), so a lifecycle or teardown fix lands in one module rather than fanning out across every spec that seeds tmux state. Idle commands are per-window, passed as a single tmux argument that tmux runs via `sh -c`. All calls use `execFileSync` argument arrays — no shell-string construction, so window names and commands need no quoting. Window-scoped commands target `=name:` exact-match (see the § Exact-Match Session Targets hazard) — `killServer` is the A/B teardown for the four scratch-socket specs.
- **`app/frontend/tests/e2e/_ready.ts`** — readiness gating. `READY_TIMEOUT` is 20s under `CI` and 10s locally; `gotoServerReady` / `gotoWindow` bundle a navigation with the `[aria-label='Connected']` sidebar-footer wait, and `resolveWindow(page, server, session, windowName?)` polls `/api/sessions` returning the full `SnapshotWindow` (`{ windowId, index, name, marker?, color? }`; omit `windowName` for the session's first) so callers project what they need from one shared poll. `openPalette(page)` is the single command-palette opener for the whole e2e tree: it presses the SHIFTED palette chord (`Shift+Control+k` — the `command-palette-alt` alias, the form that survives terminal focus because the seam refuses shifted-tier matches on every platform, [ui/keyboard-and-palette](/run-kit/ui/keyboard-and-palette.md) § Alias bindings), gates on the palette input, and returns it for chaining. A bounded blur-and-retry backs it up for a chord lost some other way; the first attempt leaves focus untouched, which is what lets focus-sensitive specs adopt it. The two tests that PROVE a raw chord survives in-frame focus (`web-tile-find` (a), `code-surface`'s reclaim spike) deliberately keep a bare press, since the retry's blur would let a broken reclaim seam pass. Specs needing open-then-fill wrap it locally (`openPaletteWith`, `openViaPalette`, `zenPalette` — which returns the DIALOG for option scoping); every one delegates the press. **Precondition**: the Connected dot lives in the sidebar footer, which unmounts when collapsed or at mobile viewport — mobile-viewport specs (`boards-mobile`, `mobile-layout`, `mobile-touch-scroll`) gate on always-mounted elements (heading, chevron, iframe) instead, and must not be migrated onto the dot.
- **`app/frontend/tests/e2e/_ports.ts`** — port derivation. `reserveDeadPort()` binds `127.0.0.1:0`, reads the assigned ephemeral port, closes the listener, and returns `{ port, url }` — the "dead web tab" URL specs stamp (dead by construction, so no fixed-port occupancy can flip the tile's live/dead posture); each file resolves it ONCE in `beforeAll` and feeds the same value to both the stamped URL and its `stubProxyPorts` calls. `startCodeStub(html)` is the single code-server stub starter (the four code-lens specs' former per-file copies): it binds the harness-seeded `RK_CODE_SERVER_PORT` when set (validated against 1–65535 with a named error — the backend forwards the stable `/code/` route to exactly that port) and an ephemeral port-0 bind when unset, returning `{ server, port }` so specs read the bound port from the return, never a constant; `plainCodeStubHtml()` and `focusGrabCodeStubHtml(delayMs)` are the two stub page bodies. Two layers plus two fold-ins. **Base API**: `pinWindow(request, board, server, windowId)` / `unpinWindow(...)` POST `/api/boards/{board}/pin|/unpin` with `{ server, windowId }` and ok-assert (`` `pin ${windowId} → ${status}` ``); they take an `APIRequestContext` (callers pass `page.request` or the `request` fixture) and use **relative** paths, which resolve for both context kinds because `playwright.config.ts` always sets `use.baseURL`. **Opt-in cleanup registry**: `trackPin(entry: PinEntry)` / `unpinAll(request)` — best-effort (try/catch per entry, no ok-assert), finishing with `registry.length = 0`; `PinEntry` carries `board` so one registry spans multiple boards (`board-autofit` pins onto two). The registry exists because pinning **moves** a window into a `_rk-pin-<id>` session that persists on the worktree's e2e primary tmux server across runs — killing the source session does not reap it, so an unswept pin pollutes later runs. **Worker-lifetime invariant**: the registry is module state living for the whole **worker process**, not the spec file — Playwright reuses workers across spec files (same `workerHash`) and never clears the module cache, so every `trackPin` caller MUST sweep via `unpinAll` in its own `afterAll` or its entries leak into the next file's sweep. Only specs that already owned a per-file `pinnedEntries` loop are on the registry; the rest let their own unpin flow or `global-teardown.ts` reap. **Exception**: `connection-budget.spec.ts`'s `finally`-block cleanup unpin stays a bare non-asserted `request.post` — a throw from `finally` would replace the in-flight try-block exception and mask the socket-count diagnostic the test exists for. Fold-ins with the same home: `apiBase(baseURL)` (`baseURL ?? http://localhost:${E2E_PORT ?? 3333}` — the harness-only env read and fail-closed fallback matching `playwright.config.ts`, for specs asserting against the raw `request` fixture) and `isTerminalsSocket(url)` (`/\/ws\/terminals(\?|$)/`, the terminals-mux classifier used by the WebSocket-counting board specs).

E2E test coverage: create/kill session via UI, state-socket delivers real data, sidebar navigation, sidebar window sync (external window creation/rename reflected within 5000ms, kill-then-create at same index does not suppress new window via stale optimistic context). A `connection-budget.spec.ts` guard asserts each route holds **≤ 2 WebSockets total — 1 `/ws/state` + (0 or 1) `/ws/terminals`** (Host and bare-server routes hold only state; Terminal and Board routes add exactly one terminals socket) and **zero `text/event-stream` responses** (260716-qf3j-state-socket) (260717-803u-relay-mux): no `EventSource` exists, so every route is 2 WS + 0 SSE. Sockets are counted as opened − closed via each ws close event (a duplicate same-URL socket is detectable; Vite HMR WS excluded). The classifier is `/ws/terminals` (not per-pane `/relay/`) — a board with N panes shows ONE terminals socket, not N relay sockets (260717-803u-relay-mux). A shared `_state-socket-mock.ts` `routeWebSocket` helper (answering `hello`→global-replay + `subscribe`→`ack`) backs every spec that mocks the state stream (there are no `page.route(...text/event-stream...)` mocks); `multi-server-sidebar:70` passes deterministically — the subscribe/ack protocol structurally closes the attachServer→SSE race. Acceptance A-014 (two board panes, one flooding, the other stays interactive — the HOL scheduler in vivo) has no committed spec; it is verified by a throwaway e2e probe (echo ~421ms under a sustained ~10MB/s co-pane flood, the flood stream kept flowing, zero `closed`/socket churn).

## Design Decisions

### The e2e palette opener defocuses only on retry, never on the first attempt
**Decision**: `_ready.ts`'s `openPalette` presses the chord with focus untouched on attempt 1; only a failed attempt blurs the active element before re-pressing, and the last attempt asserts rather than probes so exhaustion costs the same three waits as success and names the palette.
**Why**: focus state is itself observable behavior that several specs assert on, so a first attempt identical to a bare press means the helper cannot change what any passing focus-sensitive spec proves. The blur is the backstop for a chord lost some other way — the chord the helper presses is the shifted alias, which terminal focus does not consume.
**Rejected**: an unconditional pre-press blur (silently mutates focus at every call site, and would let a broken iframe-reclaim seam pass in the tests that prove it); a bare bounded retry with no focus handling (a no-op when focus is stably in the terminal, which is the failure being fixed); a Playwright `test.extend` fixture (heavier than the plain-module precedent).
*Introduced by*: 260830-my49-harden-e2e-palette-opener

### Shared frontend test scaffolding is imported per-test, never auto-installed via `setupFiles`
**Decision**: `src/test-utils/` (fixture factories + `stubMatchMedia`) is a plain importable module; `setupFiles` stays `["./src/test-setup.ts"]`, which carries only unconditional environment polyfills. See § Frontend Unit Tests.
**Why**: some suites deliberately assert real or *absent* matchMedia behavior — `tip.test.tsx` `delete`s `window.matchMedia` to restore jsdom's default — so a global auto-install would silently change what those tests prove, and an opt-in import keeps each file's control over its own environment explicit. It is also the smallest blast radius: pure test-code movement, zero production edits.
**Rejected**: registering the stub in `test-setup.ts` (breaks the assert-absent suites and hides the environment mutation from the file under test); a required-overrides `makeWindow` variant for the two sites needing `windowId`+`index` (a second signature to maintain when an explicit per-call override reads fine).
*Introduced by*: 260731-5hm6-frontend-vitest-test-utils

### `stubMatchMedia` covers only the predicate family; controllable-MQL stubs stay bespoke
**Decision**: the shared helper owns the fire-and-forget shape (per-query `matches`, `vi.fn()` listener stubs); tests that fire change events or inspect listener bookkeeping keep building their own MQL object and stubbing via `mockReturnValue(mql)`.
**Why**: the two families differ in kind, not degree — a controllable MQL is the *subject* of those tests, so folding it behind a predicate argument would either leak a mock-plumbing parameter into every caller or force the helper to grow an event-emitting MQL implementation no predicate-family caller wants.
**Rejected**: one universal `matchMedia` helper parameterized over both shapes (a two-mode helper whose modes share only a name); migrating the mql family to the predicate helper (would delete the behavior those suites exist to prove).
*Introduced by*: 260731-5hm6-frontend-vitest-test-utils

### Shared Go test scaffolding is one `internal/testutil` package with layered opt-in helpers, not per-package `testhelpers_test.go`
**Decision**: the stub-executable fixture and the deadline-poll wait loop live in a single importable `rk/internal/testutil`, with each behavioral divergence across call sites expressed as an **explicit API layer** rather than flattened away: PATH-prepend is a separate `StubOnPath` function over the base `WriteStub` (so PATH-*replacing* callers keep their own `t.Setenv`), and fail-on-expiry is a separate `MustWaitUntil` over the fall-through `WaitUntil`. Shapes that resist the `cond func() bool` contract stay bespoke by design — see § Testing / Go Unit Tests for the enumerated exclusions.
**Why**: a single package is discoverable — code-quality.md's "duplicating existing utilities" anti-pattern tells authors to check `internal/` first, and these two families span 5 and 13 call sites respectively — enough reach that any hand-rolled copy diverges on the axes the layers name (PATH replacement vs prepend, `t.Fatalf` vs fall-through-and-assert). Making each divergence a named layer means a call site's choice is visible at the call site rather than buried in a local helper's body, so the consolidation preserves every site's exact semantics — a hard requirement, since the constitution's Test Integrity rule forbids changing what tests prove to suit test infrastructure.
**Rejected**: leaving the duplication (copies drift on exactly the two axes the layers name); per-package `testhelpers_test.go` files (re-duplicates across packages — the same problem one directory down, and `_test.go` helpers are not importable across packages); one flattened helper per family with a behavior flag or an always-prepend PATH (silently changes the semantics of the sites that replace PATH); a dedicated `_test.go` for `testutil` itself (every migrated caller exercises it, and the package is not linked into the production binary).
*Introduced by*: 260731-4404-go-internal-testutil

### Board e2e pin cleanup is an opt-in registry layer over universal ok-asserted base helpers, and `finally`-block cleanup stays non-asserted
**Decision**: `_boards.ts` splits the pin surface in two: `pinWindow`/`unpinWindow` are ok-asserted and universal, while `trackPin`/`unpinAll` are adopted only by specs that own a per-file `pinnedEntries` + `afterAll` loop. `connection-budget.spec.ts`'s `finally`-block cleanup unpin is a deliberate carve-out from the ok-assert rule. See § Testing / Playwright E2E Tests.
**Why**: pin cleanup is correctness-critical but not universal — a pin moves a window into a `_rk-pin-<id>` session that outlives the source session on the worktree's shared e2e primary server, yet many specs reap their own pins through the unpin flow under test or `global-teardown.ts`, so auto-registering every pin would change those specs' cleanup semantics under a behavior-preserving consolidation. Keeping the registry opt-in also keeps the sweep obligation legible at the call site, which matters because the registry's real lifetime is the **worker process**, not the spec file: Playwright reuses workers across files and never clears the module cache, so an unswept file leaks its entries into the next file's sweep. In the `finally` block, a throw replaces the in-flight try-block exception, which would mask the socket-count diagnostic the test exists for.
**Rejected**: a `pinTracked` convenience combining pin + track (hides the layer boundary and the sweep obligation that comes with it — call sites compose the two explicitly); a Playwright fixture via `test.extend` (heavier than the `_tmux.ts`/`_ready.ts` plain-module precedent, and per-worker fixture scoping would not remove the sweep obligation); routing `afterAll` sweeps through the ok-asserted `unpinWindow` (an already-gone pin would fail teardown for a condition that is expected); homing the pin helpers in `_ready.ts`/`_tmux.ts` (boards are an HTTP-API concern, not readiness or tmux lifecycle).
*Introduced by*: 260731-2kio-board-e2e-helpers

### Intent lives in a JSDoc block above each test
**Decision**: Per-`test()` `/** Proves: … Steps: … */` block plus one file-header comment for shared setup; there are no companion documentation files.
**Why**: The intent text moves in the same diff hunk as the test, so drift is visible in review; sibling companion files had no consumer (no CI step, script, or skill read them) and had drifted into a shadow memory layer carrying change-ID citations and history narration.
**Rejected**: A CI drift-check over the companion files (tooling to protect an unread artifact); companion files only for long specs (two conventions is worse than one).
*Introduced by*: 260828-0daa-retire-spec-md-companion-docs

### Valid-layout fixtures use surviving surface kinds
**Decision**: tests that need a *valid* multi-surface stored layout build it from
surviving kinds (`main-left:tty,code,web`), not from a retired kind converted to
a heal expectation.
**Why**: the fixture's intent is a valid 3-surface layout; swapping in a
surviving kind preserves that intent with minimal churn, while invalid-layout
healing is already covered by dedicated heal tests.
**Rejected**: converting the case to a heal expectation (changes what the test
proves; healing is covered elsewhere).
*Introduced by*: 260904-0mrk-chat-lens-residual-code-trim

B2 · your literal ask marker slider — why it fights the vocabulary
▾ fab-kit
pipe · 1px
dotted · 3px

solid · 3px
double · 6px
thick · 6px
hatch · 6px

Widths are 1/3/3/3/6/6/6/6 — not monotonic, and dotted/dashed/hatch/block are pattern classes, not weights (the picker study rejected "five weights of one device" as mushy). Making the 8 markers a progress scale re-introduces exactly that ordinal reading, and a user who set hatch = "hazard" would read as "75% done". Keep markers categorical; give progress its own axis (B1).
B3 · variant ladder as filled stops, not a bar
▾ fab-kit
buffed-pika · 2/5
swift-mink · 4/5
iron-heron · 5/5
Discrete stops make the step count legible (2/5 vs 4/5) and stacked rows don't weld into one wall of color the way full-height bars do. Cost: it no longer reads as a "stripe", so it visually collides less with the categorical stripe when both are set — arguably a plus. Same gesture as B1.

Open question for B1/B3: is the stage manual (you scrub it — a personal "how far along am I" note, like @rk_win_note) or derived (fab's .status.yaml progress map, which already knows intake→apply→review→hydrate→ship→review-pr)? The rendering is identical; the write path isn't. My lean: ship manual first (no new backend derive), leave the option name generic so a derived writer can stamp the same channel later — the status-pyramid pattern.

Suggested other improvements (small)

  • Desktop hover has two competing lights. Even with the zone gone, on hover the row background shifts and the trailing cluster fades in and the flyout arms. Consider not shading the row background on hover when the card is about to open — let the card + cluster be the hover signal, and keep the shade only for the held state (card open), which the code already distinguishes (:404-410).
  • Held-row cue on mobile. The rail steps up a shade when held, but the row body doesn't; on a 36px row the eye lands on the name, not the rail. Mirror the desktop held-row text brightening onto the coarse row so the "which row is this card about" question is answered on the row itself.
  • PR glyph slot on mobile is always reserved (16px) even for rows without PRs — that's by design for column alignment, but with the dot zone gone it's the only fixed dead width left. Keep it; just noting it's now the whole cost.
  • Stripe left inset. The stripe sits at x=4 on both pointers. If B0/B1 pull the desktop name to 18px, move the stripe to x=2 so the 6px-class markers don't crowd the dot.

# run-kit Architecture — tmux Runner

## The `internal/tmux` Package

All tmux operations via `os/exec.CommandContext` with argument slices; the package's own call sites wrap with `context.WithTimeout` (10s) via `withTimeout()`, while the exported `Run`/`RunOutput` runner core is deliberately caller-timeout-owned (see § tmux Runner Core).
`InstallHint(goos, lookPath)` (`install_hint.go`) is the shared platform-aware tmux install-hint helper — pure over an injected `exec.LookPath` (no subprocess), consumed by the doctor tmux row and the daemon-start precheck (§ Daemon Lifecycle → Tmux-presence precheck).
`version.go` owns the tmux version floor (3.4): `FloorMajor`/`FloorMinor`/`FloorString` are the single source of truth; the release grammar lives once in the unexported `parseVersionToken` (`3.2a`, `3.4` — a major.minor pair with optional letter suffix; anything non-release, including probe failures, is **unknown** — never an error), consumed by two entry shapes — the pure `ParseVersion` (strips the `tmux ` prefix of client `tmux -V` output) and the bare `#{version}` token.
`Version.BelowFloor()` implements the `>=` floor semantics; `Version.OlderThan(other)` is the strict major.minor drift predicate (suffix-only differences are never older — the doctor drift note fires only when the binary is strictly newer than a running server).
Two probes share the `RunOutput` runner core with caller-owned timeout ctx: `CurrentVersion(ctx)` probes the PATH tmux binary (through the tmux-guard shim to the real binary — exactly the binary every run-kit tmux call uses) via `-V`, and `ServerVersion(ctx, server)` probes a RUNNING server's version via `display-message -p '#{version}'` with `serverArgs` targeting (the `#{version}` format variable reports the server's version, unlike `-V` which reports the on-disk client) — callers must target only servers already confirmed live (`ListServers`), since a tmux client command on a dead socket can resurrect a server; every failure is unknown, mirroring `CurrentVersion`.
`UpgradeHint(goos, lookPath, raw)` (`install_hint.go`) composes the one below-floor message all four consumers render byte-identically (daemon-start warning, `rk serve` startup warning, doctor tmux note, remote-tunnels gate) — a brew-first ladder (darwin → `brew upgrade tmux`; linux+brew → `brew install tmux`; linux without brew → install Homebrew, then `brew install tmux`) that deliberately never recommends apt (apt cannot deliver ≥ 3.4 on the frozen-LTS releases where the warning fires).
Commands target the dedicated `runkit` server via `-L runkit` prefix (built by `runkitPrefix()`); config path defaults to `~/.config/run-kit/tmux.conf`, overridable via the `tmux_conf` settings key or the `RK_TMUX_CONF` env escape, resolved to absolute path at init.
`ConfigPath()` getter exposes the resolved path.
`OriginalTMUX` package-level var captures `$TMUX` before `init()` strips it (via `os.Unsetenv("TMUX")`) — used by `cmd/rk/riff.go` (and `agent_hook.go`) to restore `$TMUX` in child process environments when targeting the caller's own tmux server.
`DefaultConfigBytes()` returns the embedded `internal/tmux/tmux.conf` content (via `go:embed`).
Read-path functions accept `context.Context` for request cancellation: `ListSessions(ctx, server)`, `ListWindows(ctx, session, server)`, `ListServers(ctx)`, plus `GetWindowOption(ctx, windowID, server, option)` (`show-options -w -qv`, the read counterpart of the window-option setters, consumed by the `/present/` handler).
`ListServers` probes sockets in parallel using a bounded goroutine pool (cap 10, semaphore channel) — N dead sockets cost ~2s instead of 2*N seconds.
Mutation functions (`CreateSession`, `KillSession`, `RenameSession`, `CreateWindow`, `CreateWindowWithOptions`, `KillWindow`, `MoveWindow`, `MoveWindowToSession`, `LinkWindowToSession`, `RenameWindow`, `SendKeys`, `SelectWindowInSession`, `SplitWindow`, `KillActivePane`, `SetWindowColor`, `UnsetWindowColor`, `SetSessionColor`, `UnsetSessionColor`, `SetWindowOptions`, `CreateWindowWithOptionsID` — creation returning the fresh window id) use `withTimeout()` / `context.Background()`.
There is no `KillPane` on the interface — panes are killed via the window id through `KillActivePane` (§IV bounds the surface); the CLI-bound `KillPaneCtx(ctx, paneID, server)` (pane-ID kill whose tmux failure IS returned, unlike the best-effort `KillActivePane`) backs `rk mux kill` (see [agent-messaging](/run-kit/agent-messaging.md)).
`MoveWindow` emits its full bubble-swap sequence as a **single `\;`-chained `tmuxExecServer` invocation** (resolving the source index exactly once via `resolveWindowSessionIndex`) so no other mutation can interleave mid-reorder — concurrent kill/move observes only the pre- or post-reorder layout, never a partially-swapped intermediate.
Insert-before / sentinel / single-step / no-op semantics apply; the destination is a positional index.
`ListSessions(ctx, server)` queries the specified tmux server, returning `SessionInfo` structs with a `Name` field plus `Color *string json:"color,omitempty"` (per-session color-value descriptor from the `@rk_ses_color` user option — field 5 of the `list-sessions` format string — normalized via `validate.NormalizeColorValue`, nil when unset/malformed; set/cleared via `SetSessionColor(session, value, server)` / `UnsetSessionColor`, a distinct option name from window `@rk_win_color` to avoid tmux option inheritance) (260615-6rnr-expand-swatch-palette-blends) plus `Windows int json:"windows"` (the session's window count from `#{session_windows}`, field 6).
The `list-sessions` format string carries **6** tab-delimited fields — `#{session_name}`, `#{session_grouped}`, `#{session_group}`, `#{session_group_size}`, `#{@rk_ses_color}`, `#{session_windows}` — parsed by `parseSessions`; `Windows` is `0` on a missing/malformed 6th field.
Group-copy sessions are dropped by `parseSessions`'s session-group filter before the structs are returned, so a `Windows` sum over the kept sessions counts each shared window once.
`ReloadConfig(server)` hot-reloads the tmux config via `source-file` on the specified server.
`ListWindows()` includes `isActiveWindow` flag from `#{window_active}`, `PaneCommand` from `#{pane_current_command}`, and raw `ActivityTimestamp` from `#{window_activity}`.
After calling `list-windows`, `ListWindows()` issues a second `list-panes -s -t <session>` call to populate `Panes []PaneInfo` on each `WindowInfo`; pane failure is non-fatal (windows returned with empty `Panes`).
`WorktreePath` continues to be sourced from `#{pane_current_path}` in the `list-windows` format string — `list-panes` is additive.
`PaneInfo` struct: `PaneID string json:"paneId"`, `PaneIndex int json:"paneIndex"`, `Cwd string json:"cwd"`, `Command string json:"command"`, `IsActive bool json:"isActive"`, `GitBranch string json:"gitBranch,omitempty"` (populated by the sessions package's `resolveGitBranches` enrichment, not by tmux), `CwdMissing bool json:"cwdMissing,omitempty"` (true when `Cwd` does not exist on disk; populated by the sessions package's `resolveCwdMissing` enrichment) (260614-nj74-sidebar-cwd-deleted-marker), `AgentState string json:"agentState,omitempty"` (`active|waiting|idle`, empty = unknown) + `AgentStateEpoch int64 json:"agentStateEpoch,omitempty"` (0 = unknown) — parsed natively from the `@rk_pane_agent_state` pane option (const `tmux.AgentStateOption`, dual-read with the retired unscoped `@rk_agent_state` — `tmux.LegacyAgentStateOption` — as fallback) (260705-dmex-generic-agent-state-tier) — and `AgentProvider string json:"agentProvider,omitempty"` + `AgentSessionRef string json:"agentSessionRef,omitempty"` — the pre-split halves of the `@rk_pane_agent_session` pane option (const `tmux.AgentSessionOption`, dual-read with the retired previous name `@rk_pane_chat` — `tmux.LegacyAgentSessionOption` — as fallback; the still-older `@rk_chat` generation is closed out for this key, neither written nor read), parsed via `parseAgentSessionRef` and zeroed by the same reconciler that governs the agent fields (260713-nh86-chat-session-identity) (260904-bf1l-agent-session-identity-rename).
Unlike the two enrichment-assigned fields these four ARE set in `tmux.go`'s `parsePanes`.
Package-level `paneFormat` var joins **11** fields with `listDelim`: `#{window_id}`, `#{pane_id}`, `#{pane_index}`, `#{pane_current_path}`, `#{pane_current_command}`, `#{pane_active}`, `#{@rk_agent_state}` (the retired agent-state name — fallback), `#{alternate_on}`, `#{@rk_pane_agent_state}`, `#{@rk_pane_chat}` (the retired agent-session name — fallback), `#{@rk_pane_agent_session}` — each option pair dual-reads the retired name under its scope-named successor (the new value wins) at zero extra subprocess, every option field riding the existing `list-panes` call (260705-dmex-generic-agent-state-tier) (260713-nh86-chat-session-identity) (260904-bf1l-agent-session-identity-rename).
`parsePanes(lines []string) map[string][]PaneInfo` parses **11**-field tab-delimited `list-panes` output (lines with `< 11` fields skipped), grouping by window id (field 0); it parses the dual-read agent-state raw (field 8 `@rk_pane_agent_state` wins, else field 6 `@rk_agent_state`) via the pure `parseAgentState(raw) (state string, epoch int64, pid int)` helper (splits on the last `:`, validates `state ∈ {active,waiting,idle}` via `isAgentState` + integer epoch + optional pid segment, else zeros) and the dual-read agent-session raw (field 10 `@rk_pane_agent_session` wins, else field 9 `@rk_pane_chat`) via `parseAgentSessionRef(raw) (provider, ref string)` (first-colon split, `isAgentProvider`/`isAgentSessionRef` validation, else `("","")` — see [agent-state](/run-kit/agent-state.md) § Agent Session Identity), and field 7 (`#{alternate_on}`) positionally — trimmed `"1"` → `PaneInfo.AltScreen` (JSON `altScreen,omitempty`); the window-level rollup lives in `internal/sessions`.
Both fields share a single **reconciler** decision (`stale`) (260713-nh86-chat-session-identity): a pid-carrying agent-state is stale when `!agentProcessAlive(pid)`, else the legacy **shell-command** fallback — `isShellCommand(cmd)` over `shellCommands = {bash,zsh,fish,sh,dash}` — decides; the agent-session option carries no pid of its own, so it borrows the same pane's agent-state liveness — when stale, **both** the agent-state fields AND the agent-session fields are zeroed (a dead/killed agent auto-clears its stranded `active` — the guppi lesson — and never leaves a live-looking session ref; plain-shell panes never surface the identity) (260904-bf1l-agent-session-identity-rename).
Malformed lines silently skipped; returns nil on empty/all-malformed input.
The convention strings (`AgentStateOption`, `AgentStateActive`/`Waiting`/`Idle`) are the single source of truth, aliased by `cmd/rk/agent_setup.go`.
See [agent-state](/run-kit/agent-state.md).
`WindowInfo` struct uses `FabChange`/`FabStage` fields, plus `AgentState string json:"agentState,omitempty"` (`active|waiting|idle`) + `AgentIdleDuration string json:"agentIdleDuration,omitempty"` — these are a **window-level rollup** over the panes' `@rk_pane_agent_state` (260705-dmex-generic-agent-state-tier) (`waiting > active > idle`, rk-formatted duration), computed in `internal/sessions`, NOT joined from `fab pane map`.
Plus `AgentProvider string json:"agentProvider,omitempty"` + `AgentSessionRef string json:"agentSessionRef,omitempty"` — the window-level agent-session rollup (the active pane's reconciled identity if set, else the first pane carrying one) computed rk-side in `internal/sessions` by the pure `rollupAgentSession(panes)`, NOT parsed here (`tmux.go` declares them; `internal/sessions` assigns them, mirroring the agent-state rollup) (260713-nh86-chat-session-identity) (260904-bf1l-agent-session-identity-rename).
Plus `Color *string json:"color,omitempty"` (color-value descriptor — `"4"` single index or `"1+3"` blend — from the tmux `@rk_win_color` user option, normalized via `validate.NormalizeColorValue`, nil when unset/malformed), plus `Panes []PaneInfo json:"panes,omitempty"`, plus `RkType string json:"rkType,omitempty"` and `RkUrl string json:"rkUrl,omitempty"` for iframe window metadata (populated from tmux user-defined options `@rk_win_lens` and `@rk_win_url` via `ListWindows` format string), plus six PR-status fields (260610-596o-pr-status-sidebar): `PrURL *string json:"prUrl,omitempty"` and `PrNumber *int json:"prNumber,omitempty"` (**derived server-side from the pane's branch** via the `internal/prstatus` branch refresher, NOT from `fab pane map` — see § Branch→PR Derivation) (260705-dmex-generic-agent-state-tier), and `PrState string json:"prState,omitempty"` / `PrChecks string json:"prChecks,omitempty"` / `PrReview string json:"prReview,omitempty"` / `PrIsDraft bool json:"prIsDraft,omitempty"` (attached at SSE-assembly time by the hub from the `internal/prstatus` viewer-wide collector snapshot, for **any** window with a derived `PrURL` — there is no change-bound gate — see § PR-Status SSE Join).
The PR/agent-rollup fields are populated outside this package; `tmux.go` declares them (and the two `PaneInfo` agent fields, which it also assigns).
`EnsureConfig()` runs the three-state managed-conf refresh at the default path (called at serve startup — § `rk serve` Wiring) and scaffolds `tmux.d/` + the `user.conf` starter on every call.
`ListKeys(server)` runs `tmux list-keys` on a server and returns raw output lines (returns nil on "no server running").
The `-f configPath` flag is scoped to `CreateSession` and `ReloadConfig` only via `configArgs()` — not passed on every command.
Both `tmuxExec` and `tmuxExecDefault` capture stderr in error messages for diagnostics.
Window-*targeting* functions take a `windowID string` (`@N`) passed directly as the `-t` target — `KillWindow(windowID, server)`, `RenameWindow(windowID, name, server)`, `SelectWindowInSession(session, windowID, server)`, `SplitWindow(windowID, horizontal, cwd, server)`, `SendKeys(windowID, keys, server)`, `KillActivePane(windowID, server)`, `SetWindowColor`/`UnsetWindowColor(windowID, …)`, `SetWindowOption(ctx, windowID, server, option, value)`/`UnsetWindowOption(ctx, windowID, server, option)` — no `session:index` target string is constructed (260529-chgz-window-id-routing).
`SelectWindowInSession` is the *session-scoped* select (`select-window -t <session>:@N`) used by both the relay (scoped to whichever session the relay attaches — the `_rk-pin-*` pin-session when the window is pinned, else the resolved home session) (260718-co9z-link-based-board-pinning) and the REST `/select` handler — a bare `select-window -t @N` is ambiguous inside a tmux session group (members share window membership but keep independent active-window state) so the scoped form is mandatory for correctness.
Positional ops keep an index destination: `MoveWindow(windowID, dstIndex, server)` resolves the source's current index from the ID (via `resolveWindowSessionIndex`) then chains the bubble-swap sequence to the target slot as one atomic `\;`-chained invocation; `MoveWindowToSession(windowID, dstSession, server)` runs `move-window -s <windowID> -t <dstSession>:`; `LinkWindowToSession(windowID, dstSession, server)` runs `link-window -s <windowID> -t =<dstSession>:` (dual membership — the window stays in its source; the board pin layer's mechanism) (260718-co9z-link-based-board-pinning).
`ResolveWindowSession(ctx, server, windowID)` resolves the window's **HOME (non-pin) session**: a targeted `display-message -t <windowID> -p '#{session_name}'` fast path, re-resolved via the unexported `resolveHomeSession` (`list-windows -a`) when the naive result is a `_rk-pin-*` name (a pinned window is a member of two sessions, so the naive lookup does not identify "exactly one session"; the pin-session is kept only when it is the window's sole link) (260718-co9z-link-based-board-pinning).
`HasSession(ctx, server, session)` is the exact-match existence probe the relay's pin-session-first attach and `Unpin`'s recovery use.
Used by the REST `/select`, `ProjectRoot`, `Pin`, and the relay's non-pinned fall-through.

**Chained `set-option` primitive** (260529-jad6-window-api-stability): `WindowOptionOp{Key string; Value *string}` is a single set-or-unset op (non-nil Value sets, nil unsets); `appendOptionOps(args, target, ops)` appends each op's `set-option -w [-u] [-t <target>] <key> [<value>]` argv, prefixing a `;` chain separator before all but the first appended op (when `target` is empty, the `-t` qualifier is omitted — used by `CreateWindowWithOptions`, where the preceding `new-window` already scopes the chained set-options to the new window).
`SetWindowOptions(ctx, windowID, server, ops []WindowOptionOp)` runs the whole batch as a single `\;`-chained `tmuxExecServer` invocation (atomic — the SSE poll never observes a half-applied state; empty ops issue no tmux call).
`CreateWindowWithOptions(session, name, cwd, server, ops []WindowOptionOp)` creates a window and atomically sets its user-defined options via that same `appendOptionOps` primitive in one chained command (prevents SSE from seeing the window before metadata is set; no separate inline option-map construction path).
`ListWindows` format string includes `#{@rk_win_color}` as field 8, `#{@rk_win_lens}` and `#{@rk_win_url}` as fields 9-10; `parseWindows` extracts them (empty string when unset).

**Active-window seam helpers** (260530-v6hm-active-window-event-derivation): `ListSessionGroups(ctx, server) (map[$sid]group, error)` runs `list-sessions -F '#{session_id}<delim>#{session_name}<delim>#{session_group}'` and parses via `parseSessionGroups` into a `$sid`→group map (ungrouped sessions, which report an empty `#{session_group}`, fall back to their own name as the group key); `rk-relay-*`/`_rk-ctl` are NOT filtered here — they must resolve to their base session's group so an event fired against an ephemeral updates the right user-facing group.
`ListActiveWindowsByGroup(ctx, server) (map[group]@wid, error)` runs `list-windows -a -F '#{session_group}<delim>#{session_name}<delim>#{window_id}<delim>#{window_active}'` and parses via `parseActiveWindowsByGroup` into a group→active-`@wid` snapshot for the Tier-1 re-seed; because `list-windows -a` reports `window_active=1` for *every* group member, only the leader row (`session_name == session_group`) is honored per group (ungrouped: own name; leaderless group: first active row as best-effort).
Both follow the `tmuxExecServer` + `context.WithTimeout(ctx, TmuxTimeout)` + pure-parse-split convention (matching `parseWindows`/`parsePanes`), return `nil` (no error) when the server is not running, and never mutate sessions (§VI).

**`CreateSession` env sanitization — direnv-diff reversal** (260706-6mpm-direnv-diff-reversal-server-env): `CreateSession` may *start* the tmux server (its `new-session -d` is the server's first client), so it runs the command under a sanitized environment AND a pinned working directory via `Run(ctx, full, RunOpts{Env: CleanEnvForServer(), Dir: ServerBirthDir()})` (the exported `CleanEnvForServer()` is shared cross-package with `tmuxctl.createAnchor`; the `dir` arg is the server-birth CWD pin, see `tmux-sessions.md` § Server-Birth CWD Pin) (260720-ji0k-pin-server-birth-cwd-home).
`CleanEnvForServer()` → `sanitizeEnv(os.Environ())` targets the semantics "as if the operator had started tmux from `$HOME`" — because an rk daemon started from inside the run-kit repo captures direnv's polluted env (`WORKTREE_INIT_SCRIPT`, `IDEAS_FILE`, `RK_PORT`, `RK_HOST`, plus `RK_DAEMON_LOG` and `DIRENV_*`) into the rk-daemon tmux server and, as the *first client* of a user server, would otherwise bake all of it into that server's global env.
`sanitizeEnv` (1) **reverse-applies `DIRENV_DIFF`** via the colocated `internal/tmux/direnv.go` helper `reverseDirenvDiff` (parses direnv's env_diff — base64url decode tolerant of padded/unpadded, then `compress/zlib` inflate, then `encoding/json` unmarshal of `{"p":{...},"n":{...}}`; **Go stdlib only — no subprocess, no runtime direnv dependency**; reversal semantics: for each key in `n`, restore its `p` value if present else remove it (direnv added it), and for each key in `p` absent from `n` restore its `p` value (direnv removed it)) — this restores the operator's *true pre-direnv env, including PATH*; (2) strips **all** `RK_*`-prefixed vars (rk adds these post-direnv so reversal misses them; the whole prefix, not just `RK_DAEMON_LOG`); (3) strips **all** `DIRENV_*`-prefixed vars including `DIRENV_DIFF` itself (direnv excludes its own state vars from the diff, so reversal leaves them).
`cleanPATH` (the POSIX default const) is a last-resort guard ONLY: `PATH=cleanPATH` is injected iff no `PATH=` entry survives, never when a PATH is already present.

**Fail-soft, always** (never fails `CreateSession` — `sanitizeEnv` returns `[]string` only, no error path): `DIRENV_DIFF` absent → pass-through + the `RK_*`/`DIRENV_*` strips; `DIRENV_DIFF` present-but-unparseable (bad base64/zlib/JSON) → a single `slog.Warn` then pass-through + strips. Only user servers **born by rk** (create-server API / session-create on a dead socket, both via `CreateSession`) have their **env** sanitized; the daemon's own launch (`internal/daemon.startSession`) keeps its **env** deliberately **untouched** so `config.Load()` still reads its `RK_PORT`/`RK_HOST` from process env (cleaning it would flip `RK_HOST` back to `127.0.0.1` and break Tailscale access). Its server-birth **CWD** IS pinned to home, though — a separate concern from env (see § Daemon Lifecycle) (260720-ji0k-pin-server-birth-cwd-home): the daemon server carries rk's env but not rk's CWD.

**Operational caveat**: already-running polluted servers keep their baked env — cleanup is operational (`tmux -L <sock> set-environment -gru VAR` per var, or a server restart), not code scope.

**Pane-side origin discovery (`rk url`/`rk notify`)**: the env strip removes `RK_PORT`/`RK_HOST` from panes on rk-born servers, so a bare `config.Load()` there would fall back to `127.0.0.1:3000` on non-default deployments. The covering daemon instead stamps its origin onto the server-scoped `@rk_srv_origin` option (`tmux.OriginOption`, `SetServerOrigin`/`GetServerOrigin` — the `SetServerRank` pattern), and the pane-side CLI resolver reads it at request time (explicit `RK_HOST`/`RK_PORT` env → validated `@rk_srv_origin` → the default — see the `url` row). Re-leaking `RK_*` env into panes remains explicitly rejected — the strip is the fix, not the bug. The protected server class lives here as well: `ProtectedOption` (`@rk_protected`), `IsProtectedServer`, `MarkServerProtected`/`UnmarkServerProtected`, and `IsGuardedServer` — the combined kill-guard predicate (rk-daemon by derivation ∨ `@rk_protected`-marked); option semantics in [tmux-sessions](/run-kit/tmux-sessions.md)

### tmux Runner Core

`internal/tmux/run.go` owns the **single** tmux subprocess-runner implementation, exported so the other backend packages delegate to it rather than carry their own copy (code-quality anti-pattern *"Inline tmux command construction — all tmux interaction goes through `internal/tmux/`"*):

```go
type RunOpts struct {
    Env []string // nil inherits the process environment without tmux client context (TMUX/TMUX_PANE scrubbed)
    Dir string   // "" inherits the process CWD
}
func Run(ctx context.Context, args []string, opts RunOpts) error
func RunOutput(ctx context.Context, args []string, opts RunOpts) ([]byte, error)
```

The fixed contract: `exec.CommandContext(ctx, "tmux", args...)` with an explicit argv slice, never a shell string (Constitution §I). `Run` uses `cmd.Run()`; `RunOutput` uses `cmd.Output()` (stdout returned, excluded from the error text). Both capture stderr separately and, on non-zero exit, wrap it as `fmt.Errorf("%w: %s", err, strings.TrimSpace(stderr))` — the stderr-in-error convention callers pattern-match on — falling back to the **bare** error when trimmed stderr is empty (so no dangling `": "`). The `%w` wrap keeps `errors.As` working with a `*exec.ExitError` target (`var exitErr *exec.ExitError; errors.As(err, &exitErr)`).

**Child-env scrub (inherit path)**: when `RunOpts.Env` is nil, the child environment is `os.Environ()` minus `TMUX` and `TMUX_PANE` — tmux client-context variables that, inherited, attribute daemon commands to the wrong pane on the target server (§ Design Decisions → The runner core scrubs tmux client context from the child env). An explicit `RunOpts.Env` passes through verbatim — the caller owns it (`CreateSession`'s `CleanEnvForServer()` is unaffected).

Two things are **deliberately not** in the core:

- **Timeouts** — the ctx is caller-owned; every call site keeps its own budget (`withTimeout()` 10s in `internal/tmux`, daemon `cmdTimeout`, riff `TmuxTimeout`, `agentHookCmdTimeout`). Centralizing them would flatten deliberately-divergent budgets and move timeout ownership away from the call site Constitution §I puts it at.
- **Socket targeting** — each caller builds its own argv prefix, because the four flavors are documented per-site semantics: `internal/tmux`'s `serverArgs(server)`, `internal/daemon`'s const `-L rk-daemon` prepend (via the thin `runTmux`/`runTmuxInDir`/`runTmuxOutput` argv-prefix wrappers), `internal/riff`'s `tmuxArgv(spec, …)` (`-L spec.Server` on the daemon path / bare + `$TMUX`-restoring `childEnv(spec)` on the CLI path), and `cmd/rk/agent_hook.go`'s `tmuxSocketArgs(tmux.OriginalTMUX)` (`-S`).

Consumers: in-package `CreateSession` (`RunOpts{Env: CleanEnvForServer(), Dir: ServerBirthDir()}`) plus `tmuxExecServer`/`tmuxExecRawServer` (which keep their line-splitting / raw-string wrapper roles over `RunOutput`); `internal/daemon`'s three wrappers; `internal/riff`'s four spawn-engine sites (`resolveWindowIDFromPane` discards the error per its best-effort contract; the other three wrap the core's error into `SubprocessErr` at the call site); and `cmd/rk/agent_hook.go`'s `writeAgentStateImpl`/`writeAgentSessionImpl` (`_ = tmux.Run(…)`, preserving the never-fail contract). `internal/tmuxctl` is unaffected — it owns the long-running `-CC` control-mode dial, the sanctioned bypass of this boundary. Out of scope by contract: sites wanting materially different semantics, e.g. `probeServerAlive`'s boolean liveness probe (no stderr capture wanted).

## Design Decisions

### One exported tmux runner core, per-site socket targeting
**Decision**: `internal/tmux` exports `Run`/`RunOutput`/`RunOpts` (§ tmux Runner Core) as the only implementation of the `exec.CommandContext("tmux", argv)` + capture-stderr + wrap-trimmed-stderr idiom; `internal/daemon`, `internal/riff`, and `cmd/rk` delegate to it.
**Why**: a hand-copied runner drifts — copies diverge on capture strategy (`CombinedOutput` vs stderr-only) and buffer type, and every fix to the idiom must then be applied N times or silently miss a copy. One implementation is what makes the code-quality rule "all tmux interaction goes through `internal/tmux/`" enforceable. `internal/tmux` holds the superset implementation (env + dir options), so exporting it is the minimal consolidation: no new package, no behavior change.
**Rejected**: unifying socket targeting along with the runner — the four flavors (`-L` const daemon socket / `-L spec.Server` / bare + restored `$TMUX` / `-S` from `tmux.OriginalTMUX`) are deliberate per-site semantics, so each caller keeps its own argv-prefix builder; centralizing timeouts in the core — Constitution §I keeps them caller-owned and the sites run deliberately different budgets; a "quiet" core variant for best-effort callers — error-discard stays at the call site (`riff.resolveWindowIDFromPane`, both `agent_hook` never-fail sites), keeping the core's contract single-shaped.
*Introduced by*: 260731-zeiy-consolidate-tmux-runner-core

### The runner core scrubs tmux client context from the child env
**Decision**: `newRunCmd` builds the child env as `os.Environ()` minus `TMUX`/`TMUX_PANE` on the inherit path (`RunOpts.Env == nil`); an explicit `Env` passes through verbatim. There is no process-global `os.Unsetenv("TMUX_PANE")` (the existing global `os.Unsetenv("TMUX")` stays as belt-and-braces).
**Why**: tmux attributes a CLI command to the pane named by `TMUX_PANE` resolved against the TARGET server, and pane ids are unique only per server — a daemon running inside a tmux pane leaks its own server's pane id into commands aimed at other servers, misattributing them to an arbitrary colliding pane. When that colliding pane's session has only a read-only client attached (any user `-r` attach), tmux refuses the mutating commands (`send-keys`) while permitting the read-only-listed ones (`set-buffer`/`paste-buffer`): the paste lands, Enter fails. The misattribution alone justifies the scrub — the wrong pane would receive the keys regardless of any client's read-only state. The runner is the single shared seam, so the daemon's HTTP sends and the `rk mux send` CLI verb are both covered. rk CLI verbs legitimately read `$TMUX_PANE` to self-identify (`rk role`, `rk tab`, `rk owntab`, the guard shim), so only spawned tmux children may lose it.
**Rejected**: Global unset (breaks `rk role`/`rk tab`/`rk owntab` self-identification); per-call-site scrubbing (34+ call sites, one missed site reintroduces the bug).
*Introduced by*: 260902-8jco-tmux-pane-env-scrub-send-failures

[ MOCK NOTES — combined shortcuts view ]

  • No tabs. One scroll, one filter. The core query is "what's the key for X?" — the answer must come from either system, so search spans everything. Tabs would make a miss in the App tab look like "unbound" when the key lives in tmux. Type in the filter above to see the cross-section behavior.
  • Jump nav instead: the sticky chip row scrolls to a section; while filtering, each chip shows its live match count — hits below the fold stay visible. This is the tabs benefit (orientation) without the search fragmentation.
  • Key map folds. The tier map is app-only (tmux prefix chords don't fit the combo model) and tall; the fold reclaims that space. Fold state could persist alongside the bindings.
  • tmux is a locked section, not a peer editor. Same idiom as shell-owned rows: 🔒 + read-only combos. The section header names the server it was read from; prefix bindings render as Ctrl+S, then key sequences. No server → one-line empty state.
  • SHELL folded into GLOBAL as a subgroup — with tmux arriving, three flavors of "locked rows" as top-level sections is too many sections.
  • ⇧⌘E compose shown as the NEW row in GLOBAL and highlighted on the map.

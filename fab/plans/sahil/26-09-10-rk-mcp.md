## Why this shape (the evidence)

- **The desktop apps speak MCP, not ACP.** ACP's "client" is the surface a
  person sits in (Zed, JetBrains, Neovim, the mobile and Telegram bridges);
  the Claude and ChatGPT desktop apps are neither ACP role. Claude Desktop
  connects to local stdio MCP servers and to remote connectors (public DNS
  required); ChatGPT Desktop connects to remote HTTPS MCP only. ACP-as-agent
  would reach a different audience through a lossy facade over a TUI
  (native permission prompts cannot become `session/request_permission`) —
  parked, see D13.
- **The two earlier MCP rejections do not apply.** Both
  (`260416-0gz9`, `260714-popk` intakes) rejected an MCP server for *agents
  already in panes*, which have a shell and read `rk skill`. The desktop
  app has no shell on the box; MCP is its only door.
- **The CLI is already most of an MCP server.** `rk help-dump` emits a
  frozen machine-readable command tree (name/path/short/usage/text); exit
  codes follow the 0/1/2 convention (`cmd/rk/exit_code.go`); every
  subprocess is an argv slice (Constitution: Process Execution). Tool names
  and descriptions fall out of Cobra `Short`/`Long`; input schemas fall out
  of each command's flag set; `rk skill` is the server's instructions block.
- **What is missing is shape, not plumbing.** Of the 27 proposed tools, the
  read verbs mostly have `--json` already (`mux sessions`, `mux capture`,
  `mux process`, `cron list`, `gui status`, `tab show`, `tab web ls`,
  `code hosts|commands`, `doctor`, `daemon status`). `mux panes`, `status`,
  `mux snapshot list`, `gui shot` do not; and no act verb prints a
  structured receipt — `mux send` prints only its report word + pane id
  (`delivered %5` / `staged %5` / `sent %5`; `unverified %5` on the exit-1
  failure path) on stdout, `riff` and
  `mux await` report only via stderr and exit code. *(Corrected at W0
  intake; the original draft said `send` printed nothing, and listed
  `mux panes`/`status` among the verbs lacking `--json` — both have it.)*
- **The new verbs are cheap.** The CLI already calls the daemon over HTTP
  (`resolveOrigin(ctx) + "/api/notify"` in `cmd/rk/notify.go`; same in
  `present.go`, `tab_wake.go`), so `rk operator request` and `rk board` are
  thin wrappers over the closed template map (9 templates in
  `api/operator.go`) and the five board routes (`api/router.go:858-862`).
- **The dependency is solved.** The official Go SDK
  (`github.com/modelcontextprotocol/go-sdk`, Google-maintained, v1.7+)
  ships stdio and streamable-HTTP transports and tool annotations. One new
  module; no protocol code of our own.

## Constitution mapping (run-kit)

- **I Security First** — allowlist default-excluded (D3); every tool call is
  an argv exec (D9), never a shell string; destructive rows carry
  `destructiveHint` so clients confirm; `/mcp` adds no auth surface of its
  own (D10) and no public exposure.
- **II No Database** — the policy table is compiled in; the server holds no
  session state beyond the live stdio pipe; nothing persisted.
- **III Wrap, Don't Reinvent** — official SDK for the protocol; the tools
  are the existing verbs, not reimplementations.
- **IV Minimal Surface Area** — one new verb (`rk mcp`), one optional route
  (`/mcp`), ~30 tools by policy; two new verb families only because their
  capabilities were already routes with no CLI door.
- **IX Uniform HTTP Verb** — the streamable-HTTP transport requires
  `POST`+`GET`+`DELETE` on `/mcp`; W0 records this as a spec-level exception
  rather than bending the transport.
- **X Hooks Carry Only the Underivable** — untouched; agent state still
  arrives via hooks; MCP only reads it.
- **Process Execution** — D9.

## Risks

- **Interim `send` receipt (W1) misleads.** Exit 0 means "delivered by the
  engine's evidence", not "the agent acted". The tool description says so
  until W2b lands; W2b is the highest-priority W2 slice for that reason.
- **Allowlist drift.** A verb renamed or re-flagged breaks its policy row
  silently. W1 adds a test that every policy row resolves to a live Cobra
  path and that every referenced flag exists.
- **Schema noise from Cobra help.** `Long` texts are written for humans in
  a terminal; some will need a `description` override in the policy row.
  Accept per-row overrides; do not rewrite CLI help for the model.
- **Client tool timeouts differ.** 45 s is a guess at the common floor;
  make it a single constant and revisit after W1 usage.
- **Two `send` receipts.** `POST /api/windows/{id}/send` already returns a
  JSON body; W2b must reuse that shape inside the envelope, not invent a
  second one (agent-messaging spec: one engine, one evidence vocabulary).
- **Constitution IX tension** on `/mcp` — resolved in W0 by explicit
  exception; if that is unacceptable, W4 is dropped and D10 closes as "no".

## Pickup protocol (for the agent taking the next change)

1. Every decision D1–D13 is closed — do not re-open any. Design authority is
   `docs/specs/mcp.md`; where this doc and the spec disagree, the spec wins
   and this doc gets a fix-up row.
2. The policy table lives in `app/backend/internal/mcp/policy.go` with a
   doctor drift-guard; a W2/W3 change adds its rows there and updates the
   spec's "Structured today" column for the verbs it graduates.
3. Never expose a verb without a policy row, and never add a tool that
   bypasses an `rk` verb (D2, D3). If a capability seems to need a bypass,
   stop and add a W3-style verb row here instead.
4. `--json` is opt-in everywhere (D5). A change that alters default CLI
   output is out of plan.
5. Update the Status line and your row when you create/merge a change.

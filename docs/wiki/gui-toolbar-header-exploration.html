GUI toolbar → tile header

Where the gui tile's session toolbar lives across the three form factors — §§1–5 fit the cluster into the header inline; §6 is the disclosure toggle and §7 the width-adaptive synthesis that supersede it. Every mock is true-size against the shipped tokens: 35px header (32 content + 3px rule), 24×24 verb buttons, 33×35 pill chips, 6px card radius, 6px stage gutters.

0What the header already is

The target is not a new surface. surface-layout.tsx:1816 already renders a 35px header on every desktop tile: kind glyph, surface name, an inset meta chip, a flex-1 spring, then the verb cluster. The tty tile already fills that spring with kind-specific controls — a find toggle, an export menu, and a bordered pane segment. A gui chip cluster goes in exactly that slot.

Finding — chips do not fit at their current size

The pill renders Control variant="chip", whose floor is 33×35px (40×40 coarse). The header's content band is 32px. So this is not a move: header chips must be re-rendered on the 24px verb-button height axis (26 coarse), content-width for the text ones. That is a real change to gui-toolbar.tsx, not a reparenting — worth deciding now because it also sets how many fit.

2Desktop — split layout needs a new fold rule

The pill folds at TOOLBAR_OVERFLOW_MIN_PX (560) of wrapper width. In the header the budget is much tighter: the name, meta chip and four layout verbs are already spending it. A gui tile in split-h on a 1280px screen is ~630px; in main-left it can be ~420px.

Open: should the fold key on the header's free width (measured after name + meta + verbs) rather than the wrapper width the pill uses? That is more correct and costs one more ResizeObserver target — but it makes the threshold constant meaningless and it has to be re-derived.

4Mobile the header does not exist here

Finding

surface-layout.tsx:1815 gates the entire header behind {!mobile && (…)}. Mobile renders one surface at a time, swapped by the top bar's switch group — there is no tile header to move anything into. And mobile is exactly where the pill carries controls nothing else offers: ⌖ pointer mode and ⌨ key bar are coarse-pointer-only chips.

Note both mobile mocks keep the ⌨ key bar docked under the canvas — that is a different component (gui-keybar.tsx) and is out of scope here.

6The disclosure toggle — one icon opens / closes it

Rather than fitting the cluster into the header, the header carries a single ⚙ toggle; clicking it opens the toolbar, clicking again closes it. This drops the fold rule (Q3) and the mobile strip (Q2) entirely — one 24×24 button fits anywhere, including the mobile top bar. It also replaces the implicit reveal (3s hide timer + 24px hover edge) with an explicit, deterministic one, which is the actual complaint.

The one thing it does not cover

A collapsed toolbar cannot hold the capture-mode indicator. That has to stay permanently in the header — a tinted meta chip beside the name. Indicator ≠ toolbar, so this is additive, not a conflict.

7Width-adaptive header — measured fold the synthesis

§6 made the toggle all-or-nothing. This refines it: the header shows as many controls as fit, in a fixed priority order, and folds the remainder into the toggle. Wide tile ⇒ everything inline and the toggle disappears. Narrow split ⇒ only screen size and the zoom functions survive. Mobile ⇒ the toggle alone.

Two rules make it coherent:

  • The toggle is an overflow affordance, not a permanent one. It renders only when something is actually folded — the standard toolbar-overflow contract. Nothing folded, no ⚙.
  • Pinned controls never fold. The capture toggle and ⚙ sit outside the adaptive zone: capture because its state must always be legible, ⚙ because it is the way to reach what folded.

Honest cost

A measured fold is more work than the current single constant. The component must measure each item once (a hidden probe row or cached offsetWidth after first paint) and re-cut on a ResizeObserver — and the measurement has to survive font loading, the coarse-pointer size bump, and label changes (1920×1080 → auto is a width change). The failure mode is benign — fold one item too many — but it needs a test that drives real widths, which jsdom cannot do, so the fold ladder wants a Playwright case rather than a Vitest one.

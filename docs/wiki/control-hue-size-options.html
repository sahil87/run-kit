Control Hue & Size Options

Two open contract decisions, both yours. §1: the interaction/state hue algebra — the green×blue mix in the first preview read as a leftover of the matrix-era green colliding with the blue accent, so here are the four coherent alternatives, live. §2: the coarse-pointer size ladder at true pixel size — open this page on your phone; every row is an honest tap target. All schemes keep the same state grammar (hover / focus ring / pressed fill-snap / latched tint / disabled) — only the hues and sizes move.

1 · Hue algebra — four coherent options

Each tile is fully live: hover the buttons, click the toggles (they latch), Tab for the focus ring, hold for pressed. The latched chips (^, a▏, ◧) are pre-latched so you can judge on-state vs hover immediately.

A · All greenmatrix heritage, single hue

One hue carries everything: hover = green ink/border, latched = green ink/border + tint fill, focus = green ring. Keeps the matrix identity undiluted; blue retires from controls entirely. Cost: on-vs-hover differs only by fill, and accent-green now competes with green-as-status (PR ✓, ok dots) everywhere.

B · All bluegreen retires to status
bar buttons + toggle
chips (one latched)

Controls speak blue, status speaks green. Hover/focus/latch all in accent blue (sweep goes blue too); accent-green becomes a pure signal hue beside red/yellow — a status dot color, never a control color. Cleanest semantic split, most "professional tool". Cost: the matrix-green identity leaves the chrome — it survives only in status signals and terminal content.

C · Neutral + greenhover is brightness, green is state
bar buttons + toggle
chips (one latched)

Hover carries no hue at all — ink/border brighten to white, the sweep is a faint white glint (still CRT, hue-free). Green appears only when something is on, so a green control always means state, never "your cursor is here". This is the Linear/VS Code grammar with matrix green kept as the meaning color. Blue retires from controls.

D · Neutral + bluehover is brightness, blue is state
bar buttons + toggle
chips (one latched)

Same neutral hover grammar as C, but state speaks the blue accent and green retires fully to status semantics (the B split) — the maximum-clarity option: white = interaction, blue = state, green/yellow/red = status. Cost: least matrix identity of the four.

How to judge: hover a latched chip in each tile — in A the on-state and hover are siblings (fill is the only difference); in B they're siblings in blue; in C/D they can never be confused because hover has no hue. Then glance at a tile from arm's length and ask "which chips are ON?" — C/D answer instantly.

2 · Coarse size ladder — open this on your phone

Every row below is a 375px-wide frame at true CSS pixels with today's 8-chip bottom-bar set. The guidelines you're recalling: Apple HIG 44×44pt, Material 48dp, WCAG 2.5.5 (AAA) 44px — today's tokens (30px top-bar, 36px chips) sit well under all of them.

36px — today's coarse token. 8 chips fit with room (316px used of 375).

40px — the compromise floor. 8 chips still fit comfortably (348px). Noticeably easier, still dense.

44px flush — Apple HIG, all 8 chips kept. Fits only edge-to-edge with a 3px gap (373 of 375). Zero slack: any 9th chip or wider glyph breaks the row.

44px, 7 chips — HIG with breathing room. One chip yields (⌥ folds into a long-press on ^, or joins the F▴ menu). The comfortable version of 44.

48px, 6 chips — Material. Two chips yield. Big and unmissable; the row starts feeling like a keyboard accessory bar rather than a chip strip.

Hybrid — 36px visual inside a 44px hit box (dashed = the invisible hit area). Fixes mis-taps without losing density — but it does not fix "looks too small": legibility and confidence stay at 36. Worth having as the technique for secondary targets even if primary chips go bigger.

3 · My lean (argue with it)

Hue: C or D — neutral hover, one accent for state. The mix you're reacting to isn't green vs blue per se; it's that hover owns a hue at all, which forces every stateful color to fight it. Make hover pure brightness and the fight ends — then green-vs-blue becomes a single brand question: C keeps matrix green as the meaning color (more run-kit), D gives the cleanest three-way semantics (white = interaction, blue = state, green/yellow/red = status). I'd take D for legibility and let green own status outright — but this is the taste call only you can make from the tiles.

Size: 44px coarse floor for both bars — top-bar buttons and bottom-bar chips — using the 7-chip row (fold ⌥ into a long-press or the F▴ menu) rather than the flush 3px-gap version, and 40px as the floor for secondary controls (menu rows, tile verbs) with the 44px hybrid hit-box. You pushed for small once, but the audit's stray list plus your own thumb agree with Apple here. Fine-pointer sizes don't move.

# run-kit UI — Quake Terminal

**Domain**: run-kit/ui

## Overview

The quake terminal is the talk-to-the-operator surface: a global overlay that slides down from under the top bar on every route (Host, tmux Server, Terminal, Board) carrying a live embedded view of the server operator's window, so a message is written and its reply read without leaving the current route. The operator window's own terminal route wears the same surface as a full page — the operator page — on every form factor (the segment strip above the tty tile, `?tab=` as its segment state, the route's compose strip forced on and footer-docked), so the drawer is a peek of the surface the page renders and openers activated on that route focus the page, never a drawer (7usy). On desktop the INPUT docks in the drawer while it is open — a compose strip at the drawer's bottom edge is the shared compose seam's one view there — while the top-bar quake launcher (`components/quake-launcher.tsx`) is the standing affordance at rest and collapses to its glyph + chord while open, the page heading never leaving the top-bar center cell; both drive ONE shared compose seam. On mobile the quake terminal has no surface of its own: every open request resolves the operator window and NAVIGATES to its ordinary terminal route, whose own chrome — the top-bar heading, the compose strip, the bottom-bar key chips, the `--bottom-bar-pad` safe-area handling — IS the mobile quake terminal. Its chat delivery and reading add no backend route and no transcript read path: delivery forks between the templated chat lane (the window-scoped operator-request `user-message` template, carrying a server-derived context envelope naming what the user was looking at) and the existing `POST /api/windows/{id}/send` agent-target lane, reading rides the existing `/ws/terminals` relay mux, and the operator-less Start affordance rides `POST /api/operator/start` ([api-and-sockets](/run-kit/api-and-sockets.md)). The desktop drawer also carries an `Operator Terminal | Operator Tasks | Cron List | Cron Log` segment strip in its one header row — Operator Tasks swaps the embedded terminal for the operator's whole tracked list (worker rows + item rows) through the shared `WatchedTable` ([routes-and-shell](/run-kit/ui/routes-and-shell.md) § Server Page WATCHED Zone), and the two cron segments swap it for the `Cron List` registry and `Cron Log` delivery history ([cron-console-tabs](/run-kit/ui/cron-console-tabs.md)) — beside the operator's live state, the operator loop's tick-age stamp, the pin, and the collapse button. The implementation is `app/frontend/src/components/quake-terminal.tsx` (the overlay plus the mobile tongue), `app/frontend/src/components/quake-launcher.tsx` (the desktop standing affordance), `app/frontend/src/components/operator-state-glyph.tsx` (the shared ◉ + live-state dot), `app/frontend/src/components/operator-context-chip.tsx` (the chat-lane chip the compose surfaces mount), and pure helpers, per-viewer stores, the ⌘J two-state machine, the pin/engaged/restore-origin slots, the shared compose seam, and the chat-subject store in `app/frontend/src/lib/quake-terminal.ts` (colocated tests throughout).

## Requirements

### Requirement: Root-layout mount; overlay, not a route
The quake terminal SHALL mount exactly once at the persistent root layout in `app/frontend/src/app.tsx` (lazy-imported beside the single `CommandPalette` mount), as an `absolute` overlay inside the main area (the `relative flex-1 min-h-0` region under the top bar), so pages below keep their layout. On desktop, opening/closing never navigates and never writes URL or tmux state — open/closed is ephemeral per-viewer component state (Constitution IV; the geometry/opacity localStorage stores below are the carve-out preferences), so a reload always starts closed; on mobile a quake terminal request IS navigation (the mobile-navigation requirement below) — open/closed has no mobile form, though the component still mounts there (the seam listener lives in it) while rendering nothing. On desktop the drawer's rendered flag FOLLOWS the ⌘J two-state machine (below): entering `open` runs the enter slide, and entering `rest` runs the exit slide. Esc releases the machine to `rest` via a bubble-phase document keydown listener that honors `defaultPrevented` (a nested modal's Escape wins — the quake terminal is a non-modal drawer, not a focus trap) and stands down when a nested `role="dialog"` renders inside the drawer root (the inline cron entry-detail panel owns that Escape — the segments requirement below). Every collapse path (Esc, the chord, the header collapse button, and an outside click while `open` — suspended while the drawer is pinned; the machine requirement below) funnels through the exit slide below — the unmount, which closes the terminal stream, fires only after the slide completes. Focus ownership on desktop splits across the two trees: the always-mounted quake launcher captures the restore origin at machine entry, and the drawer's own machine-follower effects focus the docked compose textarea once it is mounted on entering `open` (caret at the end of any draft carried over from the standing box) and run the ownership-gated restore on returning to `rest` — under the two invariants the machine requirement below states: an origin inside any quake-terminal-owned element is never recorded, and the restore runs only while the docked textarea still owns focus, checked while the drawer is still mounted through the exit slide. (02jx) (m5lo)

### Requirement: True quake slide, mounted through exit (desktop drawer)
The desktop drawer SHALL slide in both directions: it mounts raised fully above the top-bar seam (the `.rk-quake-closed` class on `.rk-quake-slide` — `transform: translateY(-102%)`, transform-only so the motion composes with the centering `translate` property — with the raised portion hidden by a dedicated `pointer-events-none absolute inset-0 overflow-clip` wrapper around the quake terminal only, not the shared main area) and transitions to rest over 240ms (`cubic-bezier(0.2, 0.9, 0.25, 1)` in `globals.css`), the raised class dropping two animation frames after mount so the transition animates. A close request drives an internal `closing` state that re-applies the raised class and holds the unmount until the root's `transform` `transitionend` fires (with a slide-duration-plus-margin timeout fallback), so the terminal stream tears down AFTER the slide, not mid-animation; a re-open mid-exit cancels the close and the drawer transitions back down from wherever the slide had reached. `prefers-reduced-motion` zeroes the transition in CSS AND skips the mounted-through-exit delay in JS (immediate unmount).

#### Scenario: Toggle from any route
- **GIVEN** a closed quake terminal on desktop
- **WHEN** the chord fires
- **THEN** the drawer slides down from fully above the top-bar seam in ~240ms
- **AND WHEN** Esc is pressed, **THEN** it slides back up and unmounts only after the transition ends
- **AND GIVEN** reduced motion, **THEN** open/close are instant

### Requirement: One document-event seam for every entry point
Every entry point that opens the quake terminal SHALL reach the layout-mounted quake terminal by dispatching the `rk:quake-terminal` document CustomEvent (`QUAKE_TERMINAL_EVENT`) via `requestQuakeTerminal(req)` in `lib/quake-terminal.ts` — never by prop threading or direct state access, because the entry points live in route shells the layout does not compose directly (the `palette:open` / `HOST_MENU_OPEN_EVENT` seam idiom). The request shape is `{ action: "toggle" | "open", server?, send?, segment? }`: on DESKTOP, `toggle` steps the ⌘J machine between `rest` and `open`, while `open` lands at `open`; entering `open` focuses the docked compose textarea through the drawer's machine-follower effect. On MOBILE both actions collapse into one navigation (the mobile-navigation requirement below). `send` carries the palette Ask-operator fallback row's query — delivered immediately once open on desktop (dropped unsent when the resolved server has no operator window, the hint line being the answer there), seeded into the operator route's compose-strip draft on mobile. An optional `segment?: QuakeSegment` selects the drawer's body segment on open — the union (`"terminal" | "tasks" | "list" | "log"`) derives from the strip's `SEGMENTS` table, the single spelling `router-url.ts`'s literal `tab` union is guarded against by a Vitest agreement test: the desktop listener applies it to the segment state after the machine transition, while the mobile arm maps any non-terminal segment to the operator route's `?tab=<segment>` search param (merged with the `?from=` origin carrier on a cross-route navigation); a request arriving on the operator window's own route — either form factor — instead takes the shared on-operator-route path, which writes `?tab=<segment>` in place (the openers requirement below); requests without `segment` see no behavior change. The event-seam entry points are the registry chord (⌘J/⇧Ctrl+J — [keyboard-and-palette](/run-kit/ui/keyboard-and-palette.md)), the palette actions `Operator: Open quake terminal`, `Operator: Show tasks`, `Operator: Show cron list`, and `Operator: Show cron log` (the latter three always carrying `segment: "tasks"` / `segment: "list"` / `segment: "log"`), the palette's Ask-operator fallback row, the status-bar `◷` clock chip ([status-signals](/run-kit/ui/status-signals.md) § Status Bar), the mobile tongue (the affordance-pair requirement below), and the top-bar overflow-menu row ([top-bar](/run-kit/ui/top-bar.md)). The sidebar pinned operator row is ordinary `onSelectWindow` navigation ([sidebar](/run-kit/ui/sidebar.md) § Operator Pinned Row), outside this event seam. The quake launcher itself is also not an event-seam entry point — it drives the shared compose seam and the machine slot directly. (02jx)

### Requirement: Openers on the operator route focus the page
The seam listener SHALL route every valid `toggle` and `open` request arriving while the current route IS the resolved operator window's own terminal route through one form-factor-neutral on-operator-route path — the page IS the surface, so no drawer ever opens there: the desktop machine, `pinnedServer`, and `pendingSend` stay untouched. The component derives that fact once as `onOperatorRoute` from the route server/window and its resolved quake terminal server/target, mirrors it into `onOperatorRouteRef` for the once-registered listener, and checks the ref immediately after the mobile early return; the mobile arm's already-on-route branch calls the same path. A request with `segment` absent or `"terminal"` — both `toggle` and `open` — focuses the page's compose strip through `focusComposeStrip()` (`lib/compose-strip-events.ts`; the strip is always mounted on the page — the operator-page requirement below — so ⌘J there puts the caret in the docked input). A request carrying a non-terminal segment writes `?tab=<segment>` in place (`navigate({ to: ".", search: (prev) => ({ ...prev, tab }), replace: true })`). A `send` payload (the palette Ask-operator fallback row's query) seeds the strip's draft via `setComposeText` (`server:windowId`-keyed) unsent — the user reviews and sends. The chord, overflow-menu row, palette actions, and palette Ask-operator fallback stay visible and actionable on that route; requests on every other desktop route retain their open/toggle, server-pin, and pending-send semantics. (7usy)

#### Scenario: Activate a quake-terminal opener on the operator route
- **GIVEN** desktop is showing the resolved operator window's terminal route
- **WHEN** the chord, overflow-menu row, palette action, or palette fallback dispatches a quake terminal request
- **THEN** the page's compose strip textarea (`compose-strip-input`) receives focus, the machine stays `rest`, and no drawer mounts
- **AND WHEN** the request carries `segment: "list"`, **THEN** the URL gains `?tab=list` in place and the page swaps to Cron List
- **AND GIVEN** the same request on another desktop route, **THEN** its ordinary open/toggle and payload behavior applies

### Requirement: The ⌘J two-state machine (desktop)
The desktop quake terminal SHALL use the `QuakeMachineState = "rest" | "open"` module slot in `lib/quake-terminal.ts` (`getQuakeMachineState` / `setQuakeMachineState` / `useQuakeMachineState`). The quake launcher (top bar) and drawer (root-layout overlay) mount in different trees and share this state owner. `cycleQuakeMachine` implements the complete chord table: `rest → open` and `open → rest`. In `rest` the drawer is closed and the quake launcher stands in the top bar; entering `open` drops the drawer, collapses the launcher to its glyph + chord, and focuses the docked compose textarea (caret at the end of any draft) once it is mounted — an effect keyed on the machine AND the drawer's mount flag, so the focus call lands after the textarea exists. The drawer remains open if focus moves into its terminal; focus movement alone does not change the machine. Entering `rest` also stands every open-scoped flag down: `setQuakeMachineState("rest")` resets the pin and the compose-`engaged` slot to `false` (the pin requirement below).

**Focus return obeys two invariants**, both of which make the quake terminal incapable of overriding a genuine user focus choice ([focus-ownership](/run-kit/ui/focus-ownership.md) § The Quake Terminal's Own Focus Return). (a) **Origin capture excludes quake-terminal-owned elements**: entering `open` records `document.activeElement` into the lib's restore-origin slot (`setQuakeRestoreOrigin` — a bare module slot shared across the two trees) ONLY when it lies outside every quake-terminal-owned element — `isQuakeTerminalTarget(origin)` false, a containment check on the `data-quake-terminal` marker both the launcher and the drawer root carry — else `null`; the capture lives in the always-mounted launcher, and a mouse entry focuses the standing input BEFORE `onFocus` transitions the machine, so an unguarded capture names the box. (b) **The return is ownership-gated**: on reaching `rest` the drawer's machine-keyed effect takes no focus action at all unless the docked compose textarea is still `document.activeElement` — the release either came from the textarea giving focus up (Esc, the chord, the header collapse button), or from the user focusing something else, and the second case already has its owner. The check MUST observe ownership while the drawer is still mounted: the drawer is mounted through the exit slide (`QUAKE_SLIDE_MS`, `finishClose`), so the effect keys on the MACHINE, not the mount flag — an effect running after unmount would see `document.body` and wrongly skip the restore. When the textarea still owns focus the effect blurs it and focuses the origin from `takeQuakeRestoreOrigin()` if still connected. The launcher's own `onFocus → open` stays: clicking or tabbing into the standing box opens the drawer, and focus-on-open then moves focus to the docked textarea (the box collapses under the pointer by design). Together the invariants mean a click into an xterm pane leaves focus in the terminal and the keystrokes reach the tmux pane; without them the two rules compose into a self-sustaining loop (the restore re-focuses the box, whose `onFocus` re-enters the machine) that no input, not even Esc, can escape. (260906-f4s6) (m5lo) The machine is the drawer's controlling state — entering `open` runs the enter slide, and entering `rest` runs the exit. Enter with a non-empty draft sends through the compose seam (the docked textarea, or the standing box at rest, which also opens the drawer). The header collapse button (`▼`, `aria-label="Collapse quake terminal"`) maps to `rest`.

**Esc is a ladder.** (1) The docked textarea's own `onKeyDown` is the first rung: on the Operator Terminal segment — and only when a terminal is actually mounted to receive focus (an operator-less drawer has nothing to yield to) — Escape calls `e.preventDefault()` and focuses the embedded terminal's xterm textarea (via the `TerminalClient` focus handle), so the document listener skips this press and the next Esc collapses; on the Tasks / Cron List / Cron Log segments the event is left alone and the collapse rung fires on the first press. (2) A CAPTURE-phase handler on the drawer root claims Escape targeted at the embedded terminal's `xterm-helper-textarea`: xterm consumes Esc as a pane keystroke, which the bubble-phase listener would honor via `defaultPrevented`, so the collapse is claimed before xterm sees the key — the pane never gets the byte. (3) The bubble-phase document `keydown` listener releases the machine to `rest`, skipping `defaultPrevented` Escapes (a nested modal's Escape wins — the quake terminal is a non-modal drawer, not a focus trap) and standing down when a nested `role="dialog"` renders inside the drawer root (the inline cron entry-detail sheet owns that Escape — the segments requirement below; a DOM check, because the listener registered at open runs before the nested layer's focus trap). Owning the release in the document listener — rather than letting the textarea handle its own Esc release — keeps one Esc from being handled twice.

**A click outside the quake terminal's own DOM while `open` also maps to `rest`** — a capture-phase `document` `click` listener gated on `isQuakeTerminalTarget(e.target)` (the same containment check the file-paste forward uses, § Quake terminal file paste/drop below), attached only while `machine === "open"` AND THE DRAWER IS NOT PINNED — while pinned the listener is not attached at all (the pin requirement below). The listener does not act inline: it snapshots `getQuakeMachineActivity()` (a counter bumped on every `setQuakeMachineState` call, including a same-value no-op) at capture time, then defers the actual collapse to a `setTimeout(…, 0)` settle check that (a) bails if the activity counter moved because a click-driven event-seam entry point already claimed the interaction and (b) bails if any `role="dialog"` OTHER than the quake terminal's own drawer is open at settle time (the settings dialog, the command palette) — a modal owns the interaction while open, so the quake terminal holding still behind it is correct regardless of where inside (or outside) the dialog the click landed; this is also what lets the settings dialog's opacity control live-apply to a quake terminal that stays open beneath it. The settle deferral is a macrotask, not a microtask: a microtask can run before React commits the same click's own state update (mounting the settings dialog, or re-rendering after a trigger's own state change), which the settle check depends on having already happened. Mobile has no machine: no quake launcher exists there and quake terminal requests navigate instead of opening anything (the mobile-navigation requirement below). (02jx)

- **THEN** the machine enters `open`, the drawer opens, and the docked compose textarea receives focus without sending
- **AND WHEN** ⌘J fires again, **THEN** the machine returns to `rest`

- **GIVEN** the quake terminal `open` on desktop
- **WHEN** a click lands outside the drawer and the quake launcher
- **THEN** the machine transitions to `rest` and the drawer unmounts through the exit slide
- **AND GIVEN** a click inside the drawer or the quake launcher, **THEN** nothing collapses
- **AND GIVEN** a click-driven event-seam entry point outside the quake terminal's own DOM, **THEN** that trigger's machine decision wins over the outside-collapse
- **AND GIVEN** a click that opens the settings dialog (or any other `role="dialog"` overlay), **THEN** the quake terminal stays open — a modal owns the interaction while it's up
- **AND GIVEN** the drawer is pinned, **WHEN** a click lands outside, **THEN** nothing collapses (the chord, Esc, and ▼ still collapse)

### Requirement: Pin — suspends only the outside-click collapse
The desktop drawer SHALL carry a pin that holds it open against click-away. Pin state is a module slot in `lib/quake-terminal.ts` beside the machine — `getQuakePinned()` / `setQuakePinned(boolean)` / `useQuakePinned()`, the machine pub/sub idiom (a module slot rather than component state because the palette builder in the top-level layout must read it for its toggle label and the drawer unmounts at rest). It is NEVER persisted (no localStorage, tmux option, or URL — Constitution IV) and `setQuakeMachineState("rest")` resets it to `false`, so every open starts unpinned — a pin on a closed drawer is meaningless. The control sits in the header row: `<button type="button" aria-pressed={pinned} aria-label={pinned ? "Unpin quake terminal" : "Pin quake terminal"} data-testid="quake-terminal-pin">⌖</button>` in the icon-button vocabulary (`rk-glint`, `coarse:` ≥36px floors, `text-accent-green` ink while pressed — the green latch, [visual-design](/run-kit/ui/visual-design.md) § Global Control-State Rules). While pinned the outside-click capture listener is NOT attached (the effect early-returns on `machine !== "open" || pinned`), so a click into the pane below the drawer leaves the drawer open and the clicked element owns the interaction; ⌘J (`toggle`), the Esc ladder, and ▼ still collapse, and the settle-timeout / activity-counter / unrelated-dialog machinery runs unchanged on the unpinned path. The palette twin is `Operator: Pin quake terminal` / `Operator: Unpin quake terminal` (id `quake-terminal-pin`, `buildQuakeTerminalPinAction(pinned)` in `lib/palette/quake-terminal.ts`, no chord), listed only while the desktop machine is `open` — degrade-to-absent, where the opener stays always-listed ([keyboard-and-palette](/run-kit/ui/keyboard-and-palette.md) § Command Palette Actions). The pin is never a focus claim: the compose-`engaged` accent borders are focus-derived, not pin-derived, so pinned-and-unfocused renders plain.

#### Scenario: Pin holds the drawer against click-away only
- **GIVEN** the drawer open and pinned
- **WHEN** a click lands in the page below the drawer
- **THEN** the drawer stays open and focus is where the click landed
- **AND WHEN** ⌘J, Esc, or ▼ fires, **THEN** the machine returns to `rest`
- **AND WHEN** the drawer is collapsed and re-opened, **THEN** it opens unpinned
- **AND GIVEN** the drawer closed, **THEN** the palette lists no pin entry

### Requirement: The quake launcher — standing affordance and collapsed control (desktop)
On desktop the quake terminal's standing pointer affordance SHALL be the quake launcher (`components/quake-launcher.tsx`) in the top bar's center cell ([top-bar](/run-kit/ui/top-bar.md) § Chrome (Top Bar) center cell), rendered on every route and resolving its server exactly as the quake terminal does (`resolveQuakeTerminalTarget` with an ephemeral last-viewed ref, the route server arriving as a prop; tolerant of a missing `SessionProvider` — degrades to "no operator"). A draft left in the shared store (a failed send, an unsent message) shows in the standing box at rest. The ◉ glyph — the shared `OperatorStateGlyph` (`components/operator-state-glyph.tsx`), consumed by every surface that names the operator — carries the resolved operator's live-state dot on every rendered form, positioned at bottom-right with a background-colored cutout ring: `active` is green, `waiting` is amber, every other resolved state is grey, and no operator means no dot. `OPERATOR_STATE_DOT` in `lib/quake-terminal.ts` owns the mapped state colors. Clicking or tabbing into the standing box engages the machine at `open` (`onFocus → open`), and focus-on-open then moves focus to the docked textarea; Enter with a non-empty draft in the standing box sends and sets `open`. (02jx) (m5lo)

At OPEN, wherever the launcher renders something at rest (the ≥lg box, the md–lg ghost), it SHALL render one collapsed control instead (`data-testid="quake-launcher-collapsed"`): a `<button type="button" aria-label="Focus quake terminal compose">` holding the `OperatorStateGlyph` (dot kept, `data-testid="quake-launcher-state"` semantics unchanged) plus the chord keycap, `h-[28px] rounded border px-1.5`; below `md` nothing renders at open either. The control carries the `data-quake-terminal` root attribute so its click never reads as an outside click, and its click re-focuses the docked compose textarea — the same-value `setQuakeMachineState("open")` re-assertion bumps the machine-activity counter the outside-click settle check honors, so the click can never collapse the drawer it targets. No input element, no engaged compose width, and no launcher-mounted context chip renders at `open` (the chip lives in the docked strip). One shared **`engaged`** flag — the module slot in `lib/quake-terminal.ts` (`setQuakeComposeEngaged` / `useQuakeComposeEngaged`), readable from both trees — says the compose owns input right now: the docked strip publishes it (true while the textarea has real focus; a blur whose `relatedTarget` lies inside the strip wrapper does NOT clear it, so the context chip's ✕ click lands), and while engaged BOTH the strip's textarea and the collapsed control carry `border-accent-green` (else `border-border`). The flag is focus-derived, never machine- or pin-derived: a blur deliberately does not release the machine (the drawer is a peek that outlives the compose's focus), so chrome never claims focus it lacks while the user types in a terminal — pinned-and-unfocused renders plain. `setQuakeMachineState("rest")` resets the flag. (m5lo)

On the operator window's own route the launcher SHALL render the collapsed control instead of the standing box or the ghost (`onOperatorRoute`, the same derivation the drawer uses — route server and window equal the resolved server and target window) — the page IS the surface, so no standing textarea renders there on any width band and the launcher never transitions the machine on that route; the control's click focuses the page's compose strip through `focusComposeStrip()`. The launcher's standing box and collapsed control both carry the quake-terminal-root attribute (`data-quake-terminal`) so the route terminals' document-level file-paste forward skips launcher-origin pastes, and the box owns its own file path — pasting an image uploads to the operator window's session and insert-stages the returned path (the file-paste requirement below). ### Requirement: Mouse resize with per-viewer geometry persistence (desktop drawer)
The desktop drawer SHALL be mouse-resizable from every exposed edge, each edge moving only its own side. Five `aria-hidden` grips render as the drawer root's last children (edges first, corners last, so a corner wins the hit test where it overlaps an edge): the **left** and **right** edges (`quake-terminal-grip-left|right` — 10px zones straddling the border 5px out / 5px in, full height, `cursor-ew-resize`), the **bottom** edge (`quake-terminal-grip-bottom` — full width, 10px straddling, `cursor-ns-resize`; the 64×12px glass tongue tab `quake-terminal-tongue-tab` renders INSIDE it flush under the border as the visual pull tab and is a valid grab by containment), and the two **bottom corners** (`quake-terminal-grip-bottom-left|bottom-right` — 16px squares at −6px, `cursor-nesw-resize` / `cursor-nwse-resize`, both axes at once). The root positions with `left: calc(50% + {centerOffsetPx}px)` and Tailwind's `-translate-x-1/2` (the centering rides the CSS `translate` property; the slide rides `transform`; `left` is the one free channel), with `maxWidth: 96vw` so the width ceiling tracks live viewport resizes; a `window` `resize` listener re-renders so the offset re-clamps against the new width — **display-only**, the store is never written by a resize. Geometry persists per-viewer in one localStorage JSON key `runkit-quake-terminal-geometry` (`{heightVh, widthPx, centerOffsetPx}`) via the geometry store in `lib/quake-terminal.ts` (the `use-local-storage-enum.ts` pub/sub idiom: same-tab subscriber notify plus the cross-tab `storage` event, with numeric clamping in place of the enum hook's allowed-list validation), read on mount with try/catch and defaults (55vh / 760px / offset 0) on absent, corrupt, or out-of-clamp values; a stored record without `centerOffsetPx` reads as offset 0 (a present-but-non-numeric offset is corrupt). ### Requirement: Glass background with a per-viewer opacity setting (desktop drawer)
The desktop drawer's background SHALL be glass: `color-mix(in srgb, var(--color-bg-primary) {α}%, transparent)` over a FIXED `backdrop-filter: blur(6px)` (+ the `-webkit-` prefix; the bottom tongue-grip shares the same background). α is a per-viewer preference stored in localStorage (`runkit-quake-terminal-opacity`, the same pub/sub store idiom as the geometry store — a read falls back to the retired `runkit-operator-console-opacity` key when the new key is absent, and a write sets the new key and removes the retired one), default 0.95, clamped 0.5–1.0, applied live to an open quake terminal via the store's same-tab notify; α = 1.0 disables the backdrop-filter entirely (the zero-cost opaque path). Blur is a constant — not configurable. The settings dialog surfaces α as a This-device row ([dialogs-and-state](/run-kit/ui/dialogs-and-state.md) § Settings Dialog) — a client-side resident of the one settings surface, NOT an `internal/settings` registry key.

#### Scenario: Glass over busy output
- **GIVEN** default settings
- **WHEN** the drawer opens over busy terminal output
- **THEN** the background shows through at α 0.95 with 6px blur and the xterm cells are transparent
- **AND GIVEN** α set to 1.0, **THEN** no backdrop-filter is applied

### Requirement: Quake terminal file paste/drop — upload to the operator's worktree, stage as insert
The quake terminal SHALL bind its own file handlers on its root (marked `data-quake-terminal`): `onPasteCapture` — CAPTURE phase, because xterm's own textarea paste handler stops propagation, so a bubble-phase handler would never see file pastes targeted at the embedded terminal — and `onDrop` (with a `dragover` preventDefault for file drags); the quake launcher binds its own `onPaste`, its wrapper carrying the same root attribute. Clipboard/dropped files ride `attachOperatorFiles` in the shared compose seam: upload via the existing `uploadFile` client (`POST /api/sessions/{session}/upload`) scoped to the OPERATOR window's session, and each returned path is delivered to the operator pane through the send lane as an INSERT — `sendToWindow(server, windowId, path + " ", "raw", "agent")`, the trailing space keeping consecutive inserts from concatenating — staged into the TUI composer where the `[Image #N]` chip renders, NEVER submitted; the user's typed message then submits normally and carries the staged image. Text paste falls through untouched (native input behavior in the quake launcher; xterm bracketed paste in the terminal). In-flight state shows the minimal "uploading…" indicator in the docked strip's status line; failures ride the inline error line and deliver nothing. With no operator window resolved, file paste is a no-op (the hint line is the answer). Route terminals' document-level strip forward MUST skip quake-terminal-origin pastes and drops ([compose-and-bottom-bar](/run-kit/ui/compose-and-bottom-bar.md) § File Upload — the `isQuakeTerminalTarget` containment guard).

#### Scenario: ⌘V of an image lands in the operator composer
- **GIVEN** an open quake terminal with a resolvable operator and an image on the clipboard
- **WHEN** ⌘V fires in the quake terminal
- **THEN** exactly one upload posts to the operator window's session and one insert-mode send delivers the returned path — and nothing lands on the tab below
- **AND** no submit fires until the user sends their message
- **AND GIVEN** an upload failure, **THEN** the inline error line shows it and nothing is delivered

### Requirement: Server-context resolution
The quake terminal SHALL resolve its server context via `resolveQuakeServer(routeServer, servers, lastViewed)`: the current route's server param always wins — read through the shared exported `useCurrentServerFromRoute()` hook (`contexts/session-context.tsx`), the single implementation of the deepest-first route-param walk, consumed by the quake terminal, `LayoutCommandPalette`'s Ask-operator gate, and the quake-terminal-context resolution below (the quake terminal additionally walks the `window` param the same deepest-first way, feeding the compose lane fork's subject); on param-less routes (Host, Board) the sole server is preselected when exactly one exists, else a header-row picker defaults to the most recently viewed server still listed (tracked ephemerally in a component ref — no persistence), then the first listed server; `null` only when the server list is empty. The operator window is discovered client-side from the sessions payload by `findOperatorWindow` (`role === "operator"` with a non-empty `windowId` — the server-scoped radio makes the first hit the only hit). The non-drawer surfaces (the mobile tongue and the quake launcher) share the same resolution through `resolveQuakeTerminalTarget` / `useQuakeTerminalContext` in `lib/quake-terminal.ts`. A pinned or picked server is scoped to the route it was requested from: navigation clears both, retargeting the quake terminal to the new route's server. (02jx)

### Requirement: Availability degrades to absent
When the resolved server has no operator window, the desktop quake terminal's Operator Terminal body SHALL render the operator-less body (`data-testid="quake-terminal-empty"`) instead of the terminal — no stream opens and no send is possible: a `Control` wide-variant Start operator button (`data-testid="quake-terminal-start-operator"`) with the hint line `no operator on this server — run rk operator` (`NO_OPERATOR_HINT`) as its sub-line (`text-text-secondary`). Click → `startOperator(server)`; pending shows `disabled` + `aria-busy="true"` + label `starting…`; on success — 202, or a structured 409 `operator_exists` (the operator appeared between render and launch) — no local transition runs: the SSE `sessions` payload carries the new `role === "operator"` window, `target` resolves, and the embedded terminal mounts in place of the body; any other error renders inline under the button (`role="alert"`, `data-testid="quake-terminal-start-error"`, `text-signal-red`, the server's message) and the button returns to idle. The client is `startOperator(server)` in `api/client.ts` — `fetch(withServer("/api/operator/start", server), { method: "POST", body: "{}" })`, `throwOnError` on non-ok, resolving `OperatorStartResult = { windowId, server }`; a 409 `operator_exists` rejects as an `ApiError` carrying `code` and `windowId` so callers treat it as success (the endpoint contract lives in [api-and-sockets](/run-kit/api-and-sockets.md)). The palette twin is `Operator: Start operator` (id `operator-start`, `buildOperatorStartAction(...)` in `lib/palette/quake-terminal.ts`), listed only while the resolved server has NO operator window (degrade to absent, never disabled) on both form factors — the only Start path on mobile, where no drawer exists — navigating to `/$server/<windowId>` on success and toasting the message on error. The operator page never renders this branch — its route requires the operator window. On mobile the tongue is omitted (never disabled) and the remaining openers (chord, palette action, palette fallback row per its existing gate, overflow-menu row) surface the same hint as a brief toast — throttled so repeats within one toast lifetime never stack — and stay put: no navigation fires when `findOperatorWindow` resolves nothing. The palette Ask-operator fallback row is omitted when its availability check can establish that no operator exists; the quake terminal openers themselves (chord, palette action, menu row) stay available — the operator-less body and the hint are the answer. (7usy)

#### Scenario: Operator-less server
- **GIVEN** a server with no `role === "operator"` window
- **WHEN** the quake terminal opens on desktop
- **THEN** the Start operator button renders above the hint sub-line, no terminal stream opens, and no send is possible
- **AND WHEN** Start operator is clicked and the backend answers 202, **THEN** the button reads `starting…` and stays disabled until the sessions payload carries the new operator window, which then mounts in the embed's place
- **AND WHEN** the backend answers 502 with a message, **THEN** the message renders inline under the button and the button returns to idle
- **AND GIVEN** a mobile viewport, **WHEN** the chord or the overflow-menu row fires, **THEN** no navigation occurs and the toast hint renders once

### Requirement: Mobile open is navigation to the operator terminal route
On mobile (the shared narrow-width-OR-coarse-pointer `useIsMobile()` rule) a quake terminal request SHALL NOT open any quake terminal surface: the layout-mounted seam listener resolves `{server, target}` (the `detail.server` pin wins, else `resolveQuakeServer(routeServer, servers, lastViewed)`; the operator window via `findOperatorWindow`) and navigates to the operator window's ordinary terminal route (`/$server/$window`) — the route's own chrome (the top-bar heading, the compose strip, the bottom-bar key chips, the `--bottom-bar-pad` safe-area handling) IS the mobile quake terminal. All three actions collapse to this navigation, idempotently: re-activating while already on the target operator route (server AND window id match) skips the navigate entirely, so an existing `?from=` (and the chip it feeds) survives. A navigation FROM a terminal route on the same server appends `?from=<originWindowId>` (never the operator window itself); the param passes the terminal route's `validateTerminalSearch` as an opaque non-empty string (`lib/router-url.ts`) and is validated against the same-server session windows at stamp time (the compose-seam requirement) — unknown, cross-server, or self ids render no chip and send direct. A `send` payload (the palette Ask-operator fallback row) seeds the operator route's compose-strip draft via the compose-draft store (`server:windowId`-keyed, `setComposeText`) instead of auto-sending — the user reviews in the strip and sends. The component still MOUNTS on mobile (the seam listener lives in it) but renders nothing; a desktop→mobile viewport flip resets the machine to `rest` and tears down any in-flight slide state so no effect or frame survives the gate (the self-gating-component rule: the gate owns the frames AND the effects). The operator-less case never navigates (the availability requirement's hide-plus-hint).

The operator route's segmented header, the `?tab=` segment contract, the hidden-not-unmounted content swap, and the forced footer-docked compose strip are form-factor-neutral page behavior — the operator-page requirement above owns them; what is mobile-only is the navigation arm itself (plus the tongue and the `?from=` origin carrier).

#### Scenario: Tongue tap on mobile
- **GIVEN** a mobile viewport on any route with an operator window on the resolved server
- **WHEN** any entry point fires
- **THEN** the app navigates to `/$server/$window` for the operator window — no quake terminal overlay mounts
- **AND GIVEN** a re-activation while already on the operator route, **THEN** no navigation fires and the current `?from=` survives
- **AND GIVEN** a navigation from a terminal route `/$srv/@5`, **THEN** the target URL carries `?from=@5` and the operator route's compose strip renders the context chip naming `@5`

## Design Decisions

### Reply channel is the live TUI embed, not transcript rendering
**Decision**: the quake terminal reads replies by embedding a live terminal view of the operator window over the existing `/ws/terminals` mux.
**Why**: Constitution X (derive over push) and the surviving tty + compose pair are the read path; the embed adds zero backend surface — no transcript endpoint, no new WS subscription kind.
**Rejected**: a transcript-rendered chat panel (rebuilds a deliberately deleted wing — backfill endpoint, live transcript stream, message rendering); an `rk say`-style push card channel (pushes state derivable from the transcript).
*Introduced by*: 260904-qa85-operator-chat-console

### Quake terminal sends are chat steers — two lanes, one allow+probe posture
**Decision**: compose delivery forks between a templated chat lane (`user-message`, carrying a server-derived source envelope, when a route-window subject resolves and the context chip is attached) and the direct chat lane (`send target:"agent"` verbatim); both deliver with allow+probe busy semantics and bypass the operator-request queue entirely.
**Why**: a template request is work handed over (busy ⇒ enqueue); a typed quake terminal message is a human steer from a user watching the pane — it must land now, whose novelty probe is the fail-closed floor. The templated lane carries the context the server derives better than the user can hand-type it (Constitution X); the registry's `chatDelivery` property gives that template the chat posture, so the fork adds context without adding queue semantics.
**Rejected**: a client-side busy gate (strands hookless operators; the probe is the floor); delivering the templated send through request semantics (busy ⇒ 202 — silently parks a live chat message while the user watches the pane); client-side context-prefix composition (spoofable and drifty — inverts Constitution X).
*Introduced by*: 260904-qa85-operator-chat-console; lane fork (260905-4xu7-operator-templated-chat-lane)

### Entry points reach the quake terminal through a document-event seam
**Decision**: the chord, palette action, palette fallback row, mobile tongue, and overflow-menu row all dispatch the `rk:quake-terminal` CustomEvent rather than threading callbacks to the layout-mounted quake terminal; the quake launcher owns the machine slot and shared compose seam directly.
**Why**: the entry points live in route shells the root layout does not compose directly; the document-event seam is the codebase's established idiom for crossing that boundary (`palette:open`, `HOST_MENU_OPEN_EVENT`, `WEB_FIND_OPEN_EVENT`).
**Rejected**: lifting open state into a new context provider with prop-threaded callbacks (a provider is easy to add later if threading deepens; the seam keeps every caller to one line).
*Introduced by*: 260904-qa85-operator-chat-console; omnibox boundary (260908-02jx-flush-surface-toggles-drop-operator-button)

### `segment` rides the existing event seam
**Decision**: the segment request is an optional field on `QuakeTerminalRequest`, applied by both form-factor arms (desktop segment state, mobile `?tab=<segment>`).
**Why**: every entry point already funnels through the one document event; a second event or a module slot would split the seam.
**Rejected**: a dedicated `rk:quake-terminal-segment` event; a URL param on desktop (the drawer is an overlay, not a route — Constitution IV).
*Introduced by*: 260910-6ehs-console-activity-segment-status-chip

### Operator Tasks renders the derived tracked list, not a fab-written HTML frame
**Decision**: the quake terminal's Operator Tasks segment renders the tracked list run-kit already derives from the fab operator state file (the whole `tracked:` set projected server-side onto `operatorTracked`, riding the sessions payload).
**Why**: the frontend already holds every fact; rendering in rk gives theme tokens, terminal font, live SSE refresh, row-click navigation, and the shared `StatusDot` channels with zero new contract surface (Constitution II and X).
**Rejected**: a fab-authored `<slug>.html` displayed by path — needs a file-serving route plus a sandboxed iframe, a polling (anti-pattern) or mtime-watch refresh story, a second cross-repo file contract beside the slug rule, and looks foreign inside the drawer.
*Introduced by*: 260911-2281-console-tasks-segment-watchlist; whole-list scope 260911-xy8b-operator-tasks-lists-all-tracked-items

### Domain-prefixed two-word segment labels
**Decision**: the segment labels are `Operator Terminal` and `Operator Tasks`; `tab` values, `?tab=` values, and internal identifiers stay `terminal`/`tasks`/`watched`.
**Why**: every segment carries its domain prefix — `Operator Terminal` and `Operator Tasks` beside `Cron List` and `Cron Log`.
**Rejected**: a bare `Tasks` label — reads as an orphan beside two-word cron siblings.
*Introduced by*: 260911-2281-console-tasks-segment-watchlist

### The operator-route and mobile arms branch on "non-terminal segment", not an enumeration
**Decision**: the on-operator-route path and the mobile navigation arm write `?tab=<segment>` for any `segment` other than absent/`terminal`.
**Why**: one rule for every non-terminal view.
**Rejected**: enumerating `tasks`/`list`/`log` at each site — a fifth segment would need three more edits.
*Introduced by*: 260911-2281-console-tasks-segment-watchlist

### Operator-route openers focus the page compose
**Decision**: on the operator route every opener focuses the compose strip (terminal segment) or writes `?tab=` in place (other segments); the drawer never opens there and the toast is retired.
**Why**: the page IS the surface; a drawer over the operator's own terminal duplicates the embed, and a toast explains an inert action that no longer needs to be inert.
**Rejected**: keeping the toast for the terminal case — it answers a question the focus already answers.
*Introduced by*: 260912-7usy-quake-terminal-operator-page

### The page's compose is the route's compose strip, not the operator compose seam
**Decision**: the operator page's docked compose is `ComposeStrip` — the route's own input, forced on and footer-docked while `operatorPage` holds; the drawer keeps `QuakeCompose`.
**Why**: mobile's operator route already uses the strip with its chat-lane fork and `?from=` chip; one route keeps one input across form factors.
**Rejected**: rendering `QuakeCompose` on the page — it would split the route's input per form factor and duplicate inputs whenever the strip preference is on.
*Introduced by*: 260912-7usy-quake-terminal-operator-page

### Start operator is an HTTP door onto `rk operator -L --json`, responding on the receipt line
**Decision**: the daemon execs its own binary (`resolveSelfPathFn`) as `operator -L <server> --json`, responds once the JSON receipt parses (30 s bound) and lets the kickoff delivery finish under a detached 90 s context.
**Why**: `rk operator` already owns creation, role-stamping, singleton probing, agent resolution and kickoff; the receipt precedes the up-to-25 s kickoff, so waiting for exit would make the button feel hung; 90 s mirrors the cron respawn's bound for the identical launch.
**Rejected**: the managed job window (`runJobFn`) — asynchronous, no `windowId` in the response; PATH-resolved `rk` — the daemon's PATH is not the user's.
*Introduced by*: 260912-7usy-quake-terminal-operator-page

### Placeholder row opens the drawer, not a synthetic route
**Decision**: the operator-less sidebar row exists on every server group the shell wires a handler for and its activation opens the drawer on Operator Terminal.
**Why**: Constitution IV's fixed route set — an overlay needs no URL, and a window-less `/$server/operator` would have to redirect once the operator exists.
**Rejected**: rendering nothing (today) — the operator's constant landmark disappears exactly when a new user needs it.
*Introduced by*: 260912-7usy-quake-terminal-operator-page

### Esc is a bubble-phase listener honoring `defaultPrevented`, not a focus trap
**Decision**: the quake terminal's Esc handling is a document keydown listener that skips `defaultPrevented` Escapes and releases the ⌘J machine to `rest` (desktop — the quake terminal has no mobile surface to close), with no focus trap.
**Why**: the quake terminal is a non-modal overlay the page stays live under; a nested modal's Escape must win, and cheap-close is the only stated requirement.
**Rejected**: the palette's modal focus-trap contract (wrong for a drawer; would capture keys the live page below still owns).
*Introduced by*: 260904-qa85-operator-chat-console

### The tongue is a toggle, mirroring desktop ⌘J
**Decision**: on the operator route the tongue renders a return state (tap = back: `?from=` origin → history back → server route) instead of hiding.
**Why**: mobile entry to the operator is one tap but exit had no standing affordance; one tab that goes in and out matches the desktop ⌘J model and uses the `?from=` fact the URL already carries.
**Rejected**: keeping the tongue hidden (one-way door); a top-bar back button (the history arrows are hidden below `lg` by the degradation ladder and a second affordance splits the model).
*Introduced by*: 260905-h7tx-operator-tongue-return-chip-glyphs

### The tongue serves mobile instead of a bottom-bar chip
**Decision**: on mobile the tongue under the top bar is the standing affordance for the quake terminal; no bottom-bar button exists.
**Why**: the bottom bar exists only on terminal tty views and its 375px single-row budget is fixed; the tongue hangs under the top bar, so it costs no bar space and works on every route.
**Rejected**: a bottom-bar chip (budget + route-scope); a hover-reveal affordance (invisible — contradicts the visual-indication goal).
*Introduced by*: 260905-sh7y-console-slide-resize-glass-paste

### Opacity is a localStorage-backed settings-dialog row
**Decision**: the quake terminal's glass α is a per-viewer localStorage key surfaced as a This-device row in the settings dialog; the blur is fixed at 6px and not exposed.
**Why**: Constitution IV layering puts per-viewer state in localStorage while "exposed in settings" is honored by the dialog being the one settings surface, which already hosts client-side residents (the terminal-font stepper); α=1 disables the filter for a zero-cost opaque path.
**Rejected**: an `internal/settings` registry key (per-instance daemon config — the wrong layer for a per-eye preference); a quake-terminal-strip-only control (the user asked for settings).
*Introduced by*: 260905-sh7y-console-slide-resize-glass-paste

### Legacy storage keys are read as fallback and removed on write
**Decision**: `readQuake*` reads the legacy `runkit-operator-console-*` key only when the new key is absent; `writeQuake*` writes the new key and removes the legacy one.
**Why**: viewers keep their drawer size and glass across the rename with no observable change; removing on write follows the `gui-posture.ts` `GUI_LEGACY_VIEW_KEY` precedent so the fallback is one-shot.
**Rejected**: leaving the legacy key orphaned — harmless but unprecedented in this codebase; migrating eagerly at module load — a write at import time, against the per-viewer-preference posture of writing only on user action.
*Introduced by*: 260912-nynf-quake-terminal-rename

### Keybinding override migration is a read-side id map, not an alias
Owned by the keybinding registry — the full four-field decision lives in [keyboard-and-palette](/run-kit/ui/keyboard-and-palette.md) § Design Decisions: `parseOverrides` maps a stored `operator-console` override onto `quake-terminal` when no new-id entry exists, and the next write drops the retired id. (260912-nynf-quake-terminal-rename)

### Attachments deliver as insert, not submit
**Decision**: quake terminal file paste/drop uploads and then delivers each returned path as a send-lane insert (staged into the TUI composer as its `[Image #N]` chip); the user's own Enter submits.
**Why**: it mirrors the TUI-composer staging behavior the injection engine's echo probe already recognizes; auto-submitting an image without its message would be wrong.
**Rejected**: appending the path to the quake terminal textarea (the path would ride the submit as plain text — the user sees raw paths and can mangle them); auto-submit per file.
*Introduced by*: 260905-sh7y-console-slide-resize-glass-paste

### Compose docks in the drawer; the launcher is a launcher
**Decision**: at `open` the shared compose seam's one view is the strip docked at the drawer's bottom edge; the top-bar launcher is the standing affordance at rest and collapses to glyph + chord while open, its click re-focusing the strip. The seam itself is untouched — draft, in-flight flags, and the inline error stay module state in `lib/quake-terminal.ts` (`useOperatorCompose` + `setOperatorComposeText` + `sendOperatorMessage` + `attachOperatorFiles`), so the send/upload logic exists exactly once and the launcher's tree (top bar) and the drawer's tree (root layout) stay in lockstep. On mobile the operator input remains the operator terminal route's own compose strip, keying its chat-lane fork on the same chat-subject store.
**Why**: the eye line becomes prompt → compose → reply at the bottom — the idiom every terminal route already uses — and the heading never loses its center cell; because draft, flags, error, and the send fork are already module state, relocating the view costs no second compose implementation.
**Rejected**: keeping the compose in the top bar (input at top, reply at bottom — a top-to-bottom eye line per exchange); a second in-drawer compose with its own state (two drafts, two error surfaces); prop-threading between the bar and the overlay (the entry-point seam idiom already rejects this); a mobile quake terminal compose of its own (the TUI-input gap — no arrows/Esc/Ctrl-C reach the pane — and the safe-area defects it carried).
*Introduced by*: 260912-m5lo-quake-terminal-docked-compose; mobile strip fork (260905-a9mn-operator-console-mobile-navigation)

### Pin suspends click-away, not the other collapse paths
**Decision**: while pinned the outside-click listener is not attached; ⌘J, Esc, and ▼ still collapse.
**Why**: the click-away collapse is right for a peek and wrong for reading the operator while typing in the pane below; the deliberate collapse gestures keep working so a pinned drawer is never stuck.
**Rejected**: a pin that also disables Esc/chord (traps the user); a "hold" modifier on the click (undiscoverable, no keyboard path).
*Introduced by*: 260912-m5lo-quake-terminal-docked-compose

### Pin is an ephemeral module slot reset at `rest`
**Decision**: pin state lives in `lib/quake-terminal.ts` beside the machine, is never persisted, and resets to `false` when the machine enters `rest`.
**Why**: the palette builder in the top-level layout must read it for its toggle label and the drawer unmounts at rest; a pin on a closed drawer is meaningless, so every open starts unpinned; Constitution IV forbids a storage write for ephemeral UI state.
**Rejected**: component `useState` in the drawer (unreadable from the palette); a localStorage key (Constitution IV; would surprise on the next open).
*Introduced by*: 260912-m5lo-quake-terminal-docked-compose

### Esc in the docked textarea yields to the terminal only where a terminal exists
**Decision**: on the Operator Terminal segment Esc focuses the embedded terminal (preventing default so the drawer's listener skips it); on the list segments — and on an operator-less terminal segment, where nothing is mounted to receive focus — the event is left alone and the collapse rung fires.
**Why**: the first rung exists so a typed message can hand keystrokes to the TUI without collapsing; where there is nothing to yield to, a dead keystroke is worse than collapsing.
**Rejected**: blur-to-body on list segments (dead key); collapsing on the first Esc everywhere (loses the yield).
*Introduced by*: 260912-m5lo-quake-terminal-docked-compose

### Glass default 0.95
**Decision**: `QUAKE_OPACITY_DEFAULT` is 0.95; the setting and its 0.5–1.0 clamp stay.
**Why**: at 0.90 busy pane output bleeds under the reply text past its contrast floor; at 0.95 the glass still reads as an overlay.
**Rejected**: 1.0 (opaque — loses the overlay cue); a per-segment opacity (a second knob for the same surface).
*Introduced by*: 260912-m5lo-quake-terminal-docked-compose

### Desktop standing affordance is the quake launcher
**Decision**: The quake launcher's standing box and md–lg ghost are the desktop standing affordance for the quake terminal, and both ◉ glyphs carry the resolved operator's live-state dot; while the drawer is open the launcher renders the collapsed glyph + chord control in the same slot. Mobile retains the tongue.
**Why**: The launcher presents the same operator glyph and opens the same two-state machine, so it carries both action and status without consuming another right-cluster slot; its collapsed form stays on screen while open as the click target that re-focuses the docked compose.
**Rejected**: A separate right-cluster ◉ control — duplicate action and fit-budget cost; omitting the dot — loses the amber `waiting` attention signal.
*Introduced by*: 260908-02jx-flush-surface-toggles-drop-operator-button

### The short placeholder does not repeat the operator glyph
**Decision**: Below `2xl` the quake launcher placeholder is `Ask…`; the standing `◉` glyph beside the input is the operator's name in the box. The placeholder is selected by the `2xl` media query alone — engaging the box never switches it to the long form.
**Why**: A placeholder that carries its own `◉` renders the box as `◉ Ask ◉…` — two operator glyphs and a dangling ellipsis that reads as a truncated label, especially beside the context chip's own truncation `…`. `Ask…` is 4ch, well inside the 12ch resting budget, and follows the codebase's trailing-ellipsis placeholder convention. The gate stays width-only because the box never widens on engagement — the compose docks in the drawer while open, so there is no engaged box state to key on — and the full 18ch form fits only the 20ch `2xl` box.
**Rejected**: `Ask the operator…` whenever engaged (there is no engaged box width to hold it); `Ask` with no ellipsis (reads as a button label, breaks the placeholder convention); a wider resting box (trades away the breadcrumbs' `lg`/`xl` width budget for a placeholder).
*Introduced by*: 260909-ae2w-omnibox-placeholder-clarity

### The ghost rung is md–lg-only
**Decision**: the dim `· ◉ ask` ghost renders only in the md–lg band; below `md` nothing renders at rest or open (the chord and palette still open the drawer), and at ≥ `lg` the standing box replaces the ghost entirely; while the drawer is open both rungs render the collapsed glyph + chord control in the same slot.
**Why**: the 640px no-overlap budget (the nav floor plus the hamburger against the anchored center heading) has no room for a standing affordance below `md`; the standing box, the ghost, and the collapsed control share one component, so the design is one thing at every width.
**Rejected**: showing the ghost below `md` (paints over the anchored heading — the forbidden overlap class); a standing box at every width (no room); hiding the launcher entirely while open (the collapsed control is the standing re-focus target for the docked compose).
*Introduced by*: 260905-sh7y-console-slide-resize-glass-paste

### Mobile quake terminal = navigation, not a parallel input surface
**Decision**: on mobile, opening the operator navigates to the operator window's ordinary terminal route; the quake terminal's mobile surface is deleted.
**Why**: the operator is a TUI — prompts need arrows/Enter/Esc/Ctrl-C, which only the terminal route's compose strip + bottom bar deliver on mobile; the route chrome also carries the top-bar heading and the `--bottom-bar-pad` safe-area handling, dissolving both reported defects with zero new code (Constitution IV).
**Rejected**: mounting ComposeStrip + BottomBar inside a mobile quake terminal surface (more parallel surface); patching the safe-area pad only (leaves the TUI-input gap).
*Introduced by*: 260905-a9mn-operator-console-mobile-navigation

### Origin context rides a `?from=` search param
**Decision**: the mobile navigation appends `?from=<originWindowId>` when navigating from a terminal route; the operator route stamps the chat subject from it and the compose strip's plain submit rides the templated chat lane behind the dismissable chip.
**Why**: preserves the chat-lane parity (server-derived envelope, Constitution X) without new persistence; the param is a route fact, visible and shareable.
**Rejected**: dropping origin context on mobile (loses the envelope the user confirmed they want); a module-store handoff without the param (invisible state, dies on reload).

### Operator-less mobile fallback is hide-plus-hint
**Decision**: the tongue hides when no operator resolves; the other openers toast the existing hint instead of navigating.
**Why**: omitted-not-disabled is the established availability pattern; the openers that remain reachable (chord, palette, menu) must answer with something — the toast is the lightest existing surface.
**Rejected**: always-visible tongue with hint-on-tap (a standing affordance that cannot act); silent no-op (indistinguishable from breakage).

### Outside-click collapse defers its decision past a settle timeout
**Decision**: the outside-click-collapse listener registers on `document` in the **capture** phase (so its activity snapshot precedes any same-click handler), but does not act inline — it defers the actual collapse to a `setTimeout(…, 0)` that re-checks `getQuakeMachineActivity()` against the value captured at click time, and separately bails if an unrelated `role="dialog"` is open. While the drawer is pinned the listener is not attached at all — the pin suspends only this click-away path (⌘J, Esc, and ▼ still collapse), so the settle machinery runs on the unpinned path only.
**Why**: a same-click event-seam trigger outside the quake terminal's DOM reads and re-writes the machine in response to the SAME click, and a click that opens an unrelated modal (the settings dialog) needs the quake terminal to stay open underneath it. Neither can be resolved by phase ordering alone: capture-then-bubble happens fully synchronously (so acting inline in capture would race the trigger's own bubble-phase handler and the not-yet-mounted dialog), and a microtask deferral is not late enough either — React's own commit of the SAME click's state update (mounting the dialog, or the button's re-render) is not guaranteed to land before a same-tick microtask. A macrotask settle is what reliably runs after that commit.
**Rejected**: acting synchronously in the capture handler (races a click-driven event-seam trigger's own handler, and an unrelated dialog is not yet mounted to check against); a microtask-based settle (same race, one tier later — insufficiently deferred relative to React's commit); a bubble-phase (or `pointerdown`) listener with no deferral at all (`pointerdown`'s mousedown→mouseup→click gap gives React enough time to flush the machine change before the trigger's own handler reads it, flipping the toggle direction).
*Introduced by*: 260907-jp91-operator-console-collapse-icon

### Outside-click containment reuses the existing quake-terminal-DOM marker; unrelated-dialog bail-out is global
**Decision**: the outside-click check excludes the quake terminal's own DOM via `isQuakeTerminalTarget`/`QUAKE_TERMINAL_ROOT_ATTR` (already applied to the drawer and the top-bar quake launcher — the collapsed control included — for recognizing quake-terminal-owned paste/drop events) rather than a new containment mechanism or tagging every entry-point trigger element; separately, the settle check bails whenever ANY `role="dialog"` other than the quake terminal's own drawer exists in the document, rather than checking the clicked target's ancestry.
**Why**: the marker already spans exactly the quake terminal's own interactive DOM, so reusing it avoids touching unrelated trigger components such as menu and palette rows — the settle-timeout deferral (above) is what protects them, not tagging. The dialog bail-out is checked globally rather than by the click target's ancestry because the trigger that OPENS a dialog (e.g. the settings gear button) is not itself inside a dialog at click time — only a global "is a dialog open right now" check, evaluated after the settle delay, catches both the opening click and every subsequent click inside the open dialog.
**Rejected**: adding the quake terminal marker to every entry-point trigger (unnecessary — the settle-timeout activity check already resolves that race, and would have required touching shared components like the sidebar row used by many non-operator rows); checking the clicked target's `role="dialog"` ancestry instead of a global existence check (misses the trigger click that opens the dialog, since the dialog doesn't exist in the DOM yet at that click).
*Introduced by*: 260907-jp91-operator-console-collapse-icon

### The activity tabs mount on the operator terminal route
**Decision**: the segmented header mounts on the existing operator-window terminal route (gated on `role === "operator"`, every form factor), not on a new overlay/sheet component.
**Why**: no mobile drawer/sheet exists — every quake-terminal-open request already navigates to the operator window's ordinary terminal route, whose own chrome IS the mobile quake terminal (the mobile-navigation decision above); a parallel overlay would duplicate that chrome.
**Rejected**: a new mobile overlay/sheet component hosting the segments (duplicates the route chrome, contradicts the navigation design); an always-on header on every terminal route (visual noise on non-operator windows — the role gate keeps every other route byte-identical).
*Introduced by*: 260907-yxen-mobile-cron-activity-feed

### Tab switch swaps content in place, keeping the terminal mounted
**Decision**: a non-terminal tab swaps the content slot to its segment body but does not unmount the terminal — the surface-layout column takes the `hidden` class and keeps its stream.
**Why**: matches the hide-never-unmount posture SurfaceLayout already applies to its own hidden tiles and the quake terminal's toggle-not-teardown behavior; switching back needs no reconnect and loses no scrollback.
**Rejected**: unmounting the terminal on tab-away (simpler, but regresses the guarantee that hidden terminals stay connected).
*Introduced by*: 260907-yxen-mobile-cron-activity-feed

### Independent edges replace symmetric-about-center
**Decision**: each edge moves only its own side — the width changes by the pointer delta and the persisted `centerOffsetPx` shifts by half of it — so the opposite edge stays put and the drawer may rest off-center.
**Why**: under symmetric width a corner grows the drawer at twice the pointer speed and cannot track the pointer; centering existed to sit under the top-bar launcher, an anchor the docked compose does not need — the quake genre needs the drawer to *open* centered, not to *stay* so.
**Rejected**: symmetric width with corners (the corner escapes the pointer); no corners (two drags for one shape).
*Introduced by*: 260912-jl4w-quake-terminal-resize

### Grip hover cue reuses the divider sash vocabulary
**Decision**: a lit edge paints a 3px accent-green inner bar with the layout dividers' 150ms anti-flicker hover-in delay (immediate on drag); a corner lights both adjacent edges, the T-junction idiom.
**Why**: one drag-affordance vocabulary across the app — the sash is already what "this seam resizes" looks like here; brushing across an edge en route to the terminal never strobes.
**Rejected**: tinting the drawer's own 1px hairline border (too faint to read as an affordance); a new grip-dot treatment (a second vocabulary for one meaning).
*Introduced by*: 260912-jl4w-quake-terminal-resize

### Viewport re-clamp is display-only
**Decision**: on `window` resize the drawer re-clamps its rendered offset without writing the geometry store.
**Why**: a transiently narrow window must not erase the viewer's preferred offset; per-viewer preferences are written only on user action (drag release, double-click, the palette reset).
**Rejected**: writing the clamped value back on resize.
*Introduced by*: 260912-jl4w-quake-terminal-resize

GUI toolbar — final proposal

The gui tile's session toolbar moves into the tile header as a width-adaptive measured fold. The floating pill is deleted. One design, one component, every form factor.
Exploration and rejected options: the companion Design Studies page.

1The proposal in one table

#DecisionRationale
D1 Controls live in the tile header's spring, at surface-layout.tsx:1816. The floating pill is removed. The slot already exists and the tty tile already uses it (⌕, ⭳, the pane segment). Nothing overlays the framebuffer; no hide timer; no 24px hover target to discover.
D2 Measured priority fold. Show as many controls as fit in a fixed order; the remainder folds into a ⚙ overflow panel. Wide tile gets everything; a narrow split keeps only what matters. No breakpoint constants to go stale.
D3 ⚙ is an overflow affordance, not a permanent one — it renders only when something is folded. The standard toolbar-overflow contract, and the same rule the top bar's chevron follows.
D4 Pinned, never folded: the ⌨ capture toggle and ⚙ itself. Their width is reserved before fitting. A mode you cannot see is a bug report; ⚙ is the way back to what folded. Mirrors the top bar's pinned switch-group reserve.
D5 Labels degrade one step before an item folds (1920×1080 ▾ → 1920 ▾, ◐ Balanced → ◐). Keeping a control reachable in terser form beats hiding it. The crumb collapse rung does the same.
D6 Fullscreen keeps the wrapper target and keeps a minimal pill. The header serves every other case. Decided: zero risk to the pan/fit and fullscreenchange seams, and no framebuffer cost where the framebuffer matters most. The pill survives for one case (§5).
D7 Mobile is the bottom rung of the same ladder — everything folded, ⌨ + ⚙ render into the top bar. No separate mobile design. Mobile has no tile header, so the pinned pair relocates; the panel is the same component.
D8 Header chrome, not pill chrome — 24px axis, borderless, secondary ink, inset hairline rules. The row must read as one cluster. Detail in §8.
D9 Constitution V intact — every chip and row stays a by-id pickGuiActions mirror; ⚙ gets its own palette rows. No toolbar-only action is introduced. The palette remains the complete registry.
D10 Three dividers, four groups: size ┆ − fit + ┆ quality ┆ all actions. No divider between icons. Dividers were doing the sprawling — five of them cost more than the gaps did. The action glyphs are one group, so they need no internal separation.
D11 Items sit flush (gap 0); the dividers carry all separation, at the shipped mx-0.5 h-3.5 w-px (2px margins, 14px hairline). The header's own flush-segment idiom (the tty pane segment). Frees ~60px, which is what pays for the pinned capture control.
D13 Capture's escape hatch is a real registry binding — gui-capture-toggle, guiOnly, shifted tier: Ctrl+Shift+G / ⌘⇧G. In capture mode the reclaim predicate narrows to that actionId alone. Remapping, a cheatsheet row and a palette entry come free, and there is no special-case chord parsing. "G" for grab — the VM/VNC vocabulary. Free in the current keymap.
D14 Capture is sticky per viewer — rk-gui-capture beside the other gui-posture.ts keys. Matches every VNC client. Safe because the header gives the indicator a permanent home — with the fullscreen carve-out in §5.
D12 Every control carries a Tip, inside one TipGroup for the cluster. Zoom tips carry their keycap; menu/cycle chips carry a dim note. A glyph-only cluster is unreadable without names. Tip adds no wrapper node, so the fold's width probe is unaffected. Detail in §7.

6Grouping, spacing, and the capture reserve

1920×1080 ▾  ┆  −fit+  ┆  ◐ Balanced  ┆  ⎘⌥▣◍∿↻   │   ⌨ ⚙

Three dividers, four groups, items flush. Each text chip earns a divider because each is a distinct kind of control — a menu, a stepper, a cycle. The six action glyphs are peers in one group and get none. Within a group items sit at gap 0.

Flush is not a new invention — it is the header's third spacing idiom, already shipping:

IdiomSpecWhere it shipsUsed here
Flush rungap 0, items touchingthe tty pane segment (Split H · Split V · Close Pane)yes — the cluster, minus the segment's border
Loose verbsgap-1.5 — 6px, direct children of the header rowthe layout verbs ⛶ ↰ ⇄ ✕kept for the header's own major parts

My earlier mock drew the divider as a full-height rule with a 6px inset. The shipped one is a short 14px hairline that never touches the header's edges — quieter, which is part of why five of them read as heavy. Corrected everywhere, inside the cluster and out.

What gap 0 buys — the capture reserve

The capture toggle does not exist yet, but the header has to have room for it when it lands. Going flush frees roughly 60px across the cluster; the pinned pair (⌨ plus its divider, and ⚙ when something is folded) costs about 30px. So the change pays for capture twice over, and the cluster still comes out ahead of where it started.

The reserve is structural, not cosmetic: the pinned block's measured width is subtracted from the budget before any ladder item is fitted — the same way the top bar reserves its trailing chevron and pinned switch group. Adding capture later can therefore only fold one more cluster item; it can never clip one, and no constant needs revisiting.

The §2 readout shows both numbers live — cluster width and pinned reserve — at whatever gap the slider is set to.

If more room is still wanted, the next lever is labels, not spacing: the glyph-only quality checkbox in §2 drops ◐ Balanced to a bare ◐, reclaiming ~55px and leaving the resolution chip as the cluster's only text.

7Tooltips — every control is named

Once the cluster is glyph-dense, names stop being optional: ∿, ⎘, ⌥, ▣, ◍ and ↻ are unreadable cold. Every control wraps in the existing Tip (components/tip.tsx) — the same component the tty header's ⌕ and ⭳ verbs already use. Hover any control in the §2 demo to see it.

Three things make this close to free:

  • Tip clones its child and adds no wrapper DOM node — its own docblock says this is so "the top-bar overflow fit's width-measurement probe" is unaffected. The pattern we are copying already accounted for the pattern we are adding.
  • It replaces the native title= (never both — the OS bubble would double the styled tip). aria-label stays and is what carries the name for screen readers.
  • It is suppressed under pointer: coarse by contract, so mobile gets no hover layer and needs no special-casing from us.

The cluster gets its own TipGroup — the warm-cluster provider, one per chrome region. Sweeping across the row opens each tip instantly (0ms) rather than paying the 300ms delay per control, which is what makes a dense glyph row actually scannable.

The carve-out: sticky capture × the fullscreen pill

Sticky capture is safe because the indicator is permanent — that was the argument for it. In fullscreen it is not: the pill self-hides 3 seconds after the last interaction, so a latched capture becomes invisible in exactly the mode where the user has the fewest other cues. Sticky then outlives its own justification.

Fix, one condition: while capture is latched, the pill's hide timer is suspended — the same way it is already suspended while one of its menus is open. The machine grows one clause, no new surface, no new state.

The alternative, if a permanently visible pill in fullscreen is unwanted: let the pill hide as usual but leave a bare ⌨ badge behind, a single latched glyph in the same top-centre position. More code, quieter result.

What D13 actually changes in the code

One predicate. gui-surface.tsx:986 asks hasReclaimableMatch(e, bindings, "gui"); in capture mode that narrows to the single gui-capture-toggle actionId. Because it is a registry binding and not a parsed chord, a user remap moves the escape hatch with it — and the tooltip and cheatsheet follow from the same source withShortcutHints already reads.

Still true regardless: in a browser tab ⌘W / ⌘T / ⌘N / ⌘Q cannot reach the guest at all. The web platform's answer is navigator.keyboard.lock(), which requires fullscreen — worth revisiting once the fullscreen pill is in place, since fullscreen is now the one mode with its own chrome path.

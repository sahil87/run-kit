Control State Audit

Inventory of every interactive control's interaction states across app/frontend/src — top bar, bottom bar, compose strip, operator console, sidebar, flyouts, menus, palette, dialogs, tile verbs — gathered 2026-09-05 by four parallel read-only sweeps. This is step 1 of the control vocabulary retrofit: the evidence base the state contract (step 2) is written against. Nothing here is a proposal; it is what the code does today, with file:line receipts.

0 · Verdict on the three bets

Bet 1 — no focus standard
Confirmed

0 focus rules in globals.css. 3 competing ring idioms across 24 call sites (outline-1 vs outline-2, accent vs accent-green). 37 of 39 outline-none sites suppress focus with no replacement.

Bet 2 — no pressed state
Confirmed

active: appears 3× in the entire frontend — two real (bottom-bar KBD_CLASS, ARROW_BTN), one cursor-only. Every compose, operator, top-bar, menu, sidebar and tile control is silent on tap.

Bet 3 — on ≈ hover confusion
Confirmed+

Four unrelated "on" vocabularies, and the unlayered glint hover actively overrides latched accent states — an on-state is not stable under hover anywhere the glint runs.

Plus one finding bigger than any bet: §2, the glint override — the root cause of most hover unpredictability — and one genuinely strong asset: the prefers-reduced-motion block (globals.css:1536-1614), which is the structural model the state contract should copy.

1 · Focus: three idioms, one constitution violation

Principle V says every action is keyboard-reachable — but reachable-and-invisible is the current state for most of the tree. There is no global :focus-visible rule; each of 24 call sites re-decides.

2 · The glint override — declared hover ≠ rendered hover

.rk-glint:hover:not(:disabled) { border-color/color: accent-green } (globals.css:266) is unlayered, so it beats every Tailwind utility on the same element. Consequences, all shipping today:

  • Dead code at ~12+ call sites: hover:border-text-secondary / hover:text-text-primary written on glint controls (TOP_BAR_BUTTON_REST, sidebar toggle, all Open/Split segments, server crumb, PR-refresh button) never renders — everything glint hovers to green regardless of what the class string says.
  • Latched states are not hover-stable: a latched Ctrl chip (text-accent, bottom-bar.tsx:382) and an on autofit toggle (text-accent, top-bar.tsx:2595) both flip to accent-green on hover — hover destroys the on-signal. And for surface toggles the on-state is green, so on ≈ hover there.
  • The :not(:disabled) guard only covers real <button>s — non-button glint elements and aria-disabled rows still glint.
  • Three visual twins deliberately omit the glint and so hover differently from neighbors sharing their exact base classes: font steppers (top-bar.tsx:2693), version-check ⟳ (top-bar-overflow-menu.tsx:585).

Contract decision this forces: either green-on-hover is the hover spec for bordered controls (then delete the dead utilities and make on-states green-safe), or the glint becomes sweep-only and call-site colors win (then move the rule into a cascade layer). One or the other — the current halfway is why hover feels unpredictable.

3 · Pressed: touch taps are silent

Since hover never fires on touch and the glint is hover-only, a coarse-pointer tap on almost any control produces zero visual feedback. The only controls with a pressed treatment are the two bottom-bar key families (active:bg-bg-card on kbd-chip.ts:9, arrow-pad.tsx:17) — ironically the surfaces that already had the best story. Missing everywhere else, including the touch-primary compose strip (compose-strip.tsx:1007-1136) and operator console.

6 · Disabled: three opacities, two disagreeing constants

88 disabled: sites: opacity-50 ×30, opacity-40 ×12, opacity-60 ×5; cursor-not-allowed accompanies only ~21. The two shared constants that encode disabled — MENU_ROW_DISABLED (40) and POPOVER_ROW_CLASS (50) — disagree with each other in the same file (top-bar-overflow-menu.tsx:65,79). Adjacent compose chips use 50 and 40. Missing entirely: the Open split-button, window-note-prompt submit (whose twin session-name-prompt has it).

7 · No primitive: 315 raw buttons, tokens in the wrong home

  • No shared Button/IconButton/Control component exists. 315 raw <button> elements across 54 files, styled by string concatenation.
  • The de-facto token module is top-bar-overflow-menu.tsx — hosted there, per its own comment, to avoid an import cycle. Real tokens deserve a real module.
  • Twins that drifted: KBD_CLASS vs ARROW_BTN (differ only in geometry, the only two complete recipes); kill-dialog buttons re-typed in board-page with text-sm dropped and raw red-900 instead of signal-red; compose Send (armed accent state) vs operator Send (none); version rows re-typing MENU_ROW_BASE by hand and dropping its flex classes; sidebar toggle hand-rolling TOP_BAR_BUTTON minus its glyph color.
  • Four menu-row scales (MENU_ROW_* xs/2.5, POPOVER_ROW_CLASS 11px/3, breadcrumb rows sm/3 with no constant, hand-rolled version rows) and per-menu ad-hoc popover container sizing over one shared-but-untokenized shell recipe.
  • Four row-hover alphas: bg-bg-card/50, /30, full, and color-mix(text-primary 8%) — four answers to "row hover".
  • Three spellings of hover-reveal for icon clusters (container pointer-events gate · same + coarse escape · button-level opacity only) — window-row.tsx:949 · status-panel.tsx:350 · host-panel.tsx:84.

8 · What already exists (build on, don't replace)

  • KBD_CLASS (kbd-chip.ts:9) is the one complete recipe — size + coarse + hover + focus-visible + active in a single constant, e2e size-asserted. It is the seed of the contract.
  • The reduced-motion block (globals.css:1536-1614) — consolidated, thorough, and it substitutes static equivalents for informational signals instead of deleting them. The state contract should be written to this standard.
  • coarse: variant cleanly defined (globals.css:27) and kept in lockstep with the JS query by documented convention.
  • Real constants with real consumers: TOP_BAR_BUTTON*, MENU_ROW_*, POPOVER_ROW_CLASS, ACTION_ROW_CLASS, MARKER_WELL_*, STATUS_RAIL_WIDTH_PX.
  • Theme tokens exist for color (--color-*, signal hues, popup shadows) — what's absent is exactly the control layer: no radius, duration, focus-ring, or control-height tokens; heights live only in TS strings, invisible to CSS.

9 · What the state contract must decide (step 2 agenda)

#DecisionRecommended default
1One focus ring Global :where(...):focus-visible rule in globals.css — outline-2 outline-accent-green, default-on for every interactive element, opt-out never silent. Kills all three idioms and covers the 37 naked suppressions at once. (Outline, not ring — ring is selection's.)
2One pressed treatment active: fill snap (bg one step up, transition-none on press) in the shared recipe — touch's only feedback channel.
3Glint: spec or garnish Decide green-hover's status (§2). Either way, move .rk-glint color rules into a cascade layer so call sites can win, and delete whichever half is dead.
4One latch vocabulary One on-treatment (tint + border + ink), hover-stable by construction; separate from selection; aria attribute drives it (aria-pressed/data-state selectors, not parallel ternaries). Open-menu triggers get a visible open state.
5Three control sizes, one floor bar 28/30 · chip 33-35/36 · row 24-or-28/36, tokenized as CSS custom properties; hard minimum 24px fine / 36px coarse for anything tappable (fixes §5's stray list; dialogs join coarse:).
6One disabled recipe opacity-40 + cursor-not-allowed + hover-neutralized, one constant.
7Token home A real controls.ts (+ CSS custom properties for heights/ring/radius/durations) — out of top-bar-overflow-menu.tsx.
8One primitive Control family (icon button · chip · toggle · segment · menu row) consuming the tokens; migrate surface-by-surface.

Migration order (each slice one fab change)

1. globals: cascade-layer the glint + the global focus-visible rule — biggest win per line, near-zero call-site churn · 2. token module + CSS custom properties · 3. top bar (already most token-aware) · 4. bottom bar + compose + operator console · 5. sidebar rows/flyouts/icon clusters · 6. menus/popovers unification · 7. dialogs + palette + coarse floors · 8. dev-only control-gallery route as the standing regression guard, screenshot-tested per pointer class.

## Why

**The pain.** Today an agent drives the host desktop with `rk gui exec xdotool …` plus `rk gui shot` plus `sleep` — the recipe on `rk skill gui`. That works only if the agent already knows xdotool's grammar, and even then it is blind in three ways the plan names: it cannot enumerate windows (so it types at whatever happens to be focused), it cannot wait for anything (so every step is a guessed `sleep`), and every look costs a full 1920×1080 PNG (the dominant token cost of a vision loop — G-D11). Two more failure modes are about the *human*: the tile follows the last fine-pointer viewer's size (parent D7), so a person resizing their laptop window mid-loop silently moves every coordinate the agent computed from its last screenshot; and the person may be driving the same pointer, which the skill page today handles with a prose gotcha ("don't fight their pointer").

**If we don't.** The code and web surfaces have first-class agent verbs with one gate, one exit-code contract, and datum-only stdout; the gui surface — the one surface where a mistake is visible to a watching human in real time — stays a bag of raw X tools. Loops stay slow (blind sleeps), expensive (full-resolution shots), and occasionally destructive (clicks landing on the wrong window after a resize or in the middle of a human's drag).

**Why this shape.** G-D10 is deliberate: rk wraps `xdotool`/ImageMagick/`xclip`/`xdg-open`, it does not reimplement them (Constitution III), and it installs none of them (toolkit `install-composition`: probe, degrade, hint). What rk adds is exactly the four things the tools lack — the shared gate and exit-code contract, one coordinate space (display pixels, with the scale factor made explicit on stderr rather than hidden), window inventory as rows/JSON with stable X ids, and the semantics X11 has no verb for: `wait --window` / `wait --stable`, a host-side resolution lock, and the human-pointer guard. The guard is the only new pushed fact and it is exactly Constitution X's carve-out — an in-flight, in-memory timestamp that exists nowhere on disk and dies with the relay.

## What Changes

All new verbs are `rk gui` children in `app/backend/cmd/rk/`, registered through the existing `init()` loop so arg-count violations exit 2 (`usageArgs`), and share the existing gate order: `guiGOOS == "darwin"` ⇒ `guiDarwinRefusal(<verb>)`; then `guiRequireReachable(ctx)` ⇒ `guiErrOff` / `guiErrNotRunning`, exit 1. Every subprocess is an argv slice under `exec.CommandContext` with a 10 s timeout (the tmux-class bound; `shot`-derived captures keep `guiShotTimeout` = 15 s). Every verb that needs an X tool probes it with `LookPath` first and refuses with the apt hint when missing; rk installs nothing. **Unchanged, byte-for-byte**: `rk gui env`/`exec`/`launch` output, `rk gui shot` stdout (the PNG path only) and default path, the gate strings, and every existing exit code (pickup protocol item 5).

### Verb surface (the plan's § Agent verbs block, binding)

```sh
rk gui windows                       # ID  PID  GEOMETRY      TITLE            (active window marked *)
rk gui windows --json                # [{id, pid, x, y, width, height, title, active, app}]
rk gui focus <id|--title <substr>>   # raise + focus; exit 1 when no match / ambiguous
rk gui click <x> <y> [--right|--middle|--double] [--window <id>]   # --window makes x y window-relative
rk gui move <x> <y>
rk gui scroll <up|down|left|right> [--n 3] [--at x y]
rk gui type <text> | --stdin         # unicode-safe (xdotool type --delay 12 via stdin), newline = Return
rk gui key <chord> [<chord>…]        # xdotool keysym spelling: ctrl+l, Return, alt+F4
rk gui shot [--out p.png] [--scale 0.5 | --max-width 1280] [--window <id>]   # stdout: path; stderr: geometry WxH scale S
rk gui wait --window <title-substr> [--timeout 10s]   # exit 0 when a window matches, 1 on timeout
rk gui wait --stable [--interval 500ms] [--timeout 10s]  # two consecutive captures identical (hash)
rk gui clip get | set <text> | set --stdin              # CLIPBOARD selection via xclip/xsel
rk gui open <url|file>               # xdg-open on the display, detached; prints `started <pid> on :N`
rk gui launch browser --cdp [--port 9222]   # G1's launcher + --remote-debugging-port; prints the port
rk gui lock | unlock                 # the D7 resolution pin; `rk gui status` shows `locked`
```

Refusals specific to G3 (all exit 1, stderr, exact copy): `human input 2s ago — retry or pass --force` (input verbs only); `xdotool not found — sudo apt install xdotool`; `no window matches "…"`; `--window <id>: not a window`. Usage errors exit 2: a bad `scroll` direction, `--scale` outside `(0, 1]`, `--scale` together with `--max-width`, `wait` with neither or both of `--window`/`--stable`, `clip` with a bad subverb, `type` with both an argument and `--stdin`, `--cdp` on the terminal role.

### `internal/gui/xdo.go` (new) — argv builders and the windows parser

Pure functions, table-tested, no X server:

- `XdoSearchVisible(display)` → `xdotool search --onlyvisible --name <pattern>` where the pattern matches every visible top-level window (the exact xdotool 3.x pattern — `""` vs `"."` — is verified at apply against the installed xdotool and pinned by a test comment; it is not a design question).
- `XdoWindowName(id)` → `getwindowname <id>`; `XdoWindowGeometry(id)` → `getwindowgeometry --shell <id>` (parsed from `WINDOW=`/`X=`/`Y=`/`WIDTH=`/`HEIGHT=` lines); `XdoWindowPID(id)` → `getwindowpid <id>` (fails when the client sets no `_NET_WM_PID` — then `pid` is 0 and `app` is empty, never an error); `XdoActiveWindow()` → `getactivewindow` (fails on a bare display with no EWMH window manager — then no row is marked active, never an error).
- `XdoActivate(id)` → `windowactivate --sync <id>`; `XdoMouseMove(x, y)` → `mousemove <x> <y>`; `XdoClick(button, repeat)` → `click [--repeat N --delay 100] <button>` with buttons 1 left / 2 middle / 3 right / 4 up / 5 down / 6 left-scroll / 7 right-scroll; `XdoType()` → `type --delay 12 --file -` (text on stdin, never argv); `XdoKey(chords...)` → `key --clearmodifiers <chord>…`.
- `Window{ID uint64; PID int; X, Y, Width, Height int; Title, App string; Active bool}` and `ParseWindows(...)` assembling rows from the per-window outputs. `App` is `/proc/<pid>/comm` (the `RunningApps` idiom) when a pid resolved.
- Every builder takes the display and returns argv only; the runner sets `DISPLAY=<display>` in the env via `gui.LaunchEnv` (xdotool reads `DISPLAY`; it has no display flag).

### `cmd/rk/gui_windows.go` (new) — `windows`, `focus`

- `rk gui windows`: rows sorted by X id; columns `ID PID GEOMETRY TITLE` (`GEOMETRY` as `WxH+X+Y`); the active window's row is marked with a trailing ` *`. `--json` emits `[{"id":…,"pid":…,"x":…,"y":…,"width":…,"height":…,"title":"…","active":true,"app":"xterm"}]` (an empty display emits `[]`). Both forms are the datum (Dataf, stdout).
- `rk gui focus <id>` / `rk gui focus --title <substr>`: `--title` is a case-sensitive substring match over the current titles (the substring is `regexp.QuoteMeta`-escaped before it reaches `xdotool search --name`, whose argument is a regex); exactly one match ⇒ `windowactivate --sync`; zero ⇒ `no window matches "<substr>"` (exit 1); more than one ⇒ `ambiguous "<substr>": <n> windows match — <id> <title>, <id> <title>` (exit 1, one line). A numeric argument that is not a window ⇒ `--window <id>: not a window`-style refusal `<id>: not a window`. `focus` is an input verb under the G-D13 guard.

### `cmd/rk/gui_input.go` (new) — `click`, `move`, `scroll`, `type`, `key`

- Coordinates are **display pixels** (G-D11), integers, `≥ 0`. `click --window <id>` first runs `getwindowgeometry` and adds the window's `X`/`Y` so `x y` are window-relative; an id that is not a window ⇒ `--window <id>: not a window`, exit 1. `click` defaults to button 1; `--right`/`--middle` pick 3/2; `--double` is `click --repeat 2 --delay 100 1`; the flags are mutually exclusive (usage). Each click is `mousemove x y` then `click`.
- `scroll <up|down|left|right> [--n 3] [--at x y]`: `--at` moves first; then `click --repeat N --delay 30 <4|5|6|7>`.
- `type <text>` / `type --stdin`: the text is split on `\n`; each segment is fed to `xdotool type --delay 12 --file -` on **stdin** (unicode-safe, no argv quoting) and a `xdotool key Return` is sent between segments — so a trailing newline produces a trailing Return. `--stdin` reads all of stdin. Empty text is a no-op exit 0.
- `key <chord> [<chord>…]`: passes the chords through verbatim in xdotool keysym spelling (`ctrl+l`, `Return`, `alt+F4`).
- **The G-D13 guard** runs before every input verb (`click`, `move`, `scroll`, `type`, `key`, `focus`) and only those — `windows`, `shot`, `wait`, `clip`, `open`, `launch`, `lock` never refuse on it. The verb fetches the status document from the daemon (§ Relay below); when `human_input_ago_ms` is present and below `guiHumanInputGrace = 3 * time.Second`, it refuses with `human input <N>s ago — retry or pass --force` (N = seconds, rounded down, minimum 1 — `human input 1s ago`) unless `--force` is set. The guard **fails open**: if the daemon's HTTP origin does not answer, no relay viewer can exist (the relay lives in the daemon), so the verb proceeds.

### `cmd/rk/gui_shot.go` — `--scale`, `--max-width`, `--window`

- `--scale <f>` (`0 < f ≤ 1`) and `--max-width <px>` are mutually exclusive (usage). `--max-width` derives `S = min(1, maxWidth / W)`. The **source geometry** `W×H` is the probe's `st.Width × st.Height` for the root capture and the window's `WIDTH×HEIGHT` from `getwindowgeometry` for `--window <id>`.
- Resize is ImageMagick: with `import` the capture is one stage, `import -display :N -window <root|id> -resize <S*100>% <out>`; with `scrot` the resize is a post-step `convert <out> -resize <pct>% <out>`; with `xwd`, `convert xwd:- -resize <pct>% <out>`. `--window <id>` maps to `import -window <id>` / `xwd -id <id>`; on the `scrot` rung `--window` is refused with `--window needs imagemagick (import or convert) — sudo apt install imagemagick` (scrot has no by-id capture; `scrot -t` is a thumbnail flag and is not used). A scale request on a host with neither `import` nor `convert` refuses with `--scale needs imagemagick — sudo apt install imagemagick`.
- **stderr always carries** `geometry WxH scale S` (a `Notef` chatter line, so `--quiet` still yields the bare path): `geometry 1920x1080 scale 0.5` for a scaled root shot, `geometry 1920x1080 scale 1` for today's default. stdout stays the absolute PNG path only. The output PNG is `round(W·S) × round(H·S)` — for the acceptance shot, 960×540.

### `cmd/rk/gui_wait.go` (new) — `wait --window`, `wait --stable`

- `wait --window <substr> [--timeout 10s]`: polls `xdotool search --onlyvisible --name <quoted substr>` every 250 ms until a window matches; on success prints the first matching window id on stdout (the datum a loop reuses instead of re-matching a drifting title — plan Risk 8) and exits 0; on expiry `timed out after 10s` (the configured duration), exit 1.
- `wait --stable [--interval 500ms] [--timeout 10s]`: captures the root at `--scale 0.25` into the OS temp dir every `--interval`, **decodes each PNG with `image/png` and hashes the pixel bytes** (SHA-256) — never the PNG file bytes, because ImageMagick writes `date:create`/`date:modify` text chunks that differ between two captures of an identical screen — and exits 0 as soon as two consecutive hashes are equal; temp captures are removed; expiry is the same `timed out after 10s`, exit 1. Needs a capture tool (the `shot` ladder's hint on miss) and, for the scale, ImageMagick (the `--scale` hint on miss).
- Both flags are required-one-of and mutually exclusive (usage, exit 2). `--timeout`/`--interval` parse as Go durations.

### Relay — the last-human-input timestamp (`api/gui_filter.go`, `api/gui_ws.go`, `api/sse.go`, `api/gui.go`)

- `newGuiViewFilter(network)` gains an **observe mode**: the client-message parser now runs on every backend. On `tcp` it keeps today's behavior (drop types 4/5 after the handshake). On `unix` the returned bytes are **always the chunk verbatim** — the parse is a side-effect only, so a parser stall or confusion can never withhold or reorder a Linux viewer's bytes (the inert guarantee is preserved for the data path).
- When a post-handshake **KeyEvent (4)**, **PointerEvent (5)**, or **QEMU client message (255) with sub-type 0 (extended key event, 12 bytes: u8 type, u8 sub-type, u16 down-flag, u32 keysym, u32 keycode)** completes, the filter calls an injected `onHumanInput()` callback; `handleGuiWS` wires it to `hub.guiHumanInputSeen(id)`, which stores `time.Now()` in `sseHub.guiHumanInputAt map[string]time.Time` under `h.mu`. noVNC sends 255/0 whenever TigerVNC advertises the QEMU Extended Key Event pseudo-encoding, which it does — plain KeyEvent alone would miss most keyboard input on this backend. The tcp drop set gains 255/0 too (the view-only posture is "no input reaches the host"; ARD servers do not advertise the encoding, so this is consistency, not a behavior change anyone observes).
- `gui.Status` and `gui.StreamEntry` gain `HumanInputAgoMS int64 \`json:"human_input_ago_ms,omitempty"\`` — computed at render time as `max(1, now − at)` in milliseconds when a timestamp exists, **omitted when none** (never seen, or the daemon restarted — the map is in-memory and dies with the process). The `≥ 1` clamp keeps "absent" and "just now" distinguishable. `gui.StatusDeps` gains `HumanInputAt func() (time.Time, bool)`; `api/gui.go`'s `buildGuiStatus` wires the hub's reader; the CLI's `gatherGUIStatus` wires nil (a CLI process cannot observe the hub — the `guiViewersFn` caveat).
- The CLI reaches the hub over HTTP: a new `guiFetchDaemonStatus(ctx) (gui.Status, bool)` in `gui.go` GETs `resolveOrigin(ctx) + "/api/gui/host"` (the `sendNotify` origin resolution: `RK_HOST`/`RK_PORT` env → the covering tmux server's `@rk_srv_origin` → `127.0.0.1:3000`) with a 2 s timeout, returning `ok=false` on any error. It is a package seam so tests script the document. Used by the guard and by `rk gui status`.
- `rk gui status` renders, when the fetched document carries `human_input_ago_ms` under the grace window, an indented line after the summary: `  human input 1s ago`. `--json` prints the fetched document when available (so `viewers` and `human_input_ago_ms` are live), else the local assembly as today.

### Lock — `rk gui lock` / `rk gui unlock` (`cmd/rk/gui.go`, `internal/daemon/gui.go`, `internal/gui/status.go`, `api/sse.go`, frontend)

- **Storage**: a session-scoped tmux user option **`@rk_gui_lock`** on the `rk-gui` session (`daemon.GUIOptionLock`), value `1` when locked, **unset** when unlocked — per-entity state lives in `@rk_*` tmux options (Constitution IV), beside the supervisor's `@rk_gui_display`/`@rk_gui_backend`/`@rk_gui_wm` stamps and read by the same `GUISessionOptions`-style seam. It **dies with the session**: `rk gui restart` and `rk gui off` clear it, which is the right lifetime for a loop-scoped pin (a stale lock cannot survive into tomorrow's session). New `daemon.SetGUILock(ctx, locked bool)` runs `set-option -t =rk-gui: @rk_gui_lock 1` / `set-option -u -t =rk-gui: @rk_gui_lock` through `runTmux`; `daemon.GUILocked(ctx) bool` reads it (unset ⇒ false).
- **Verbs**: `rk gui lock` / `rk gui unlock` share the gate (enabled + reachable — a lock on a dead display is meaningless) and print `locked` / `unlocked` (Dataf); both idempotent. Not input verbs — no G-D13 guard.
- **Readers**: `gui.Status.Locked bool \`json:"locked"\`` and `gui.StreamEntry.Locked bool \`json:"locked"\`` (always present, like `wm`); `gui.StatusDeps.Locked func(ctx) bool`; the hub's `guiTick` reads the option on the same tick as the stamps and puts `Locked` on the `event: gui` entry; `guiOnSummary` appends `, locked` as the **last** paren segment when set — `gui: on (Xtigervnc, :10, 1920x1080, 1 viewer, icewm-session, locked)` — so `rk gui status` and the doctor row (which shares `guiOnSummary`) render it identically.
- **The tile honors it** (`app/frontend/`): `src/api/client.ts` `GuiEntry.locked: boolean` (and `GuiStatus.locked`); `src/components/gui-surface.tsx` `rfb.resizeSession = !p.coarsePointer && p.focused && !p.resizeLocked && !p.hostLocked` where `hostLocked = gui?.locked ?? false` rides `propsRef` and re-applies on every stream entry change (the existing `applyRfbProps` path). The palette's `GUI: Lock resolution` / `Unlock resolution` rows stay **viewer-local** and unchanged — the host pin is an additional AND term, not a replacement, so G2/C3 semantics and tests are untouched; a viewer-side "host locked" indicator is out of scope. Vitest: the `resizeSession` truth table gains the `locked: true` row; the state-socket fixtures gain `locked: false`.

### `cmd/rk/gui_clip.go` (new) — `clip get | set <text> | set --stdin`

- Tool ladder `xclip` then `xsel`, probed by `LookPath`: get = `xclip -selection clipboard -o` / `xsel --clipboard --output`; set = `xclip -selection clipboard -i` / `xsel --clipboard --input` with the text on stdin. Neither present ⇒ `no clipboard tool found (tried xclip, xsel) — sudo apt install xclip`, exit 1. `DISPLAY` via `gui.LaunchEnv`.
- `get` prints the clipboard verbatim on stdout (the datum; no trailing newline added). `set` prints nothing, exit 0.
- **Process-handling constraint (load-bearing)**: `xclip -i` and `xsel --input` fork a child that *owns* the X selection and serve paste requests for as long as the clipboard holds that value — on the IceWM desktop there is no clipboard manager, so that child **is** the clipboard. The `set` runner therefore attaches no stdout/stderr pipes (a Go `Wait` would otherwise block on the inherited pipe until the timeout) and never kills the forked child; the context timeout bounds only the parent's exit. `clip set` is not an input verb (not in G-D13's six) — it never refuses on the guard.

### `cmd/rk/gui_open.go` (new) — `open <url|file>`

- An argument with a URL scheme (`^[a-zA-Z][a-zA-Z0-9+.-]*:`) is a URL; anything else is a file path made absolute with `filepath.Abs` (a missing file is `open: <path>: no such file`, exit 1). Runs `xdg-open <target>` detached (`gui.StartDetached` with `gui.LaunchEnv`) and prints `started <pid> on :N` (the `exec --detach` datum). Not an input verb.
- `xdg-open` missing: for a **URL** the verb falls back to the G-D5 browser ladder (`gui.ResolveApp(AppBrowser)`), starting `<browser> <url>` detached, and on a ladder miss prints `gui.LaunchHint(browser)` (`no browser on the GUI host — sudo apt install chromium-browser`), exit 1 — this is what the plan's acceptance line ("starts the browser, or exits 1 with the browser hint") describes; for a **file** it refuses with `xdg-open not found — sudo apt install xdg-utils`, exit 1.

### `cmd/rk/gui_launch.go` — `launch browser --cdp [--port 9222]`

- `--cdp` is accepted only with the `browser` role (`terminal` ⇒ usage, exit 2) and only for a **Chromium-family** resolution (`chromium`, `chromium-browser`, `google-chrome`, `google-chrome-stable`, or `x-www-browser` whose `filepath.EvalSymlinks` basename is one of those) — Playwright's `connectOverCDP` is Chromium-only, so a Firefox CDP endpoint would serve no consumer; `firefox` ⇒ `--cdp needs a Chromium-family browser (resolved firefox)`, exit 1.
- Argv: `<path> --remote-debugging-port=<N> --user-data-dir=<gui.StateDir()>/cdp-<N>` — the dedicated profile dir is what makes the flag take effect when another instance of the same browser is already running (plan Risk 10). `--port` defaults to 9222. After the existing `started <name> (pid <p>) on :N` line the verb waits ≤ 5 s (200 ms polls) for `127.0.0.1:<N>` to accept a TCP connection, then prints a second datum line `cdp http://127.0.0.1:<N>`; on expiry `cdp port <N> did not open within 5s (browser pid <p> is running)`, exit 1.

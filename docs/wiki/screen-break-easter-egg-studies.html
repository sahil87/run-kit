Screen Break Easter Egg Studies

Design study for a one-shot, whole-viewport Easter egg in which the run-kit screen cracks open and something comes out of the monitor. The mock is the real mechanism, not a picture of it: the app shell gets an evenodd clip-path hole, the cracks draw in as dashed SVG strokes, glass shards from the hole fly out under gravity, and the thing inside is clipped to the hole until it is physically through, then released in front. Three candidates for what comes out (a green fist, the brand cube, an eye), the six-frame storyboard, the layer stack, a row-scale micro version for the sidebar force-kill, the trigger table, and the recorded decisions. Everything here is CSS transforms and SVG attribute updates on a handful of elements; nothing samples pixels.

Reduced motion shows what the user with prefers-reduced-motion gets: nothing. The whole layer never mounts, same as every flair.

Reduced motion on: every mock below is frozen at t = 0 (intact screen). There is no static fallback frame by design: a crack that does not animate reads as a broken UI, so the egg is all or nothing.

1. The live break

comes out: click anywhere on the screen to set the impact point and replay · the eye follows your pointer
The 4.2 s timeline: impact (flash + 160 ms shake, radial cracks shoot out) → shatter (two ring cracks, the hole opens, nine glass shards tumble out and fall) → emerge (the thing inside is clipped to the hole, grows toward the viewer, and is released in front once it is through) → hold → retreat → heal (hole closes, cracks fade). The screen behind the hole is the "inside of the monitor": a dark ground with a glow in the creature's color, so the hole reads as depth, not as a missing rectangle. Cracks are clipped by the same evenodd path as the app, so they vanish where the hole is.

Notes

  • One clip path, two uses. The hole polygon string is written once per frame; the app's clip is "M0 0H1V1H0Z " + hole with evenodd, the creature's clip is hole alone. Both <clipPath>s use clipPathUnits="objectBoundingBox" so one set of normalized coordinates fits whatever size the shell is. In the real app the geometry is generated in px from window.innerWidth/Height and normalized the same way.
  • Geometry is seeded, not random. A tiny LCG with a fixed seed makes every run identical for a given impact point, which is what makes a storyboard and a screenshot test possible. The impact point is the only input.
  • No pixel capture. html2canvas-style approaches are out (CSP, cost, the xterm canvases). The hole is real because the shell is clipped; the shards are glass-tinted polygons, not copies of the UI. This is the trade that keeps the whole thing at ~30 DOM nodes and transform/opacity/attribute updates only.
  • Where it mounts. A single <ScreenBreak /> at the app-shell root, sibling of the toast layer, rendered only while an egg is in flight and unmounted at the end. It owns the ground, the two SVGs, the sprite and the <defs>; the shell receives only a style.clipPath and a transform for the shake. Same discipline as FlairOverlay: aria-hidden, pointer-events: none, no JS timers besides one requestAnimationFrame loop for the 4.2 s.
  • Reduced motion. The prefersReducedMotion() helper the logo sweep already uses gates the mount. No static fallback (see the toolbar note).
  • verify early Repaint cost of clipping the shell. clip-path on the element that contains the xterm canvases may force the terminals to repaint every frame. If it stutters on a full-width terminal, fall back to clipping only a fixed dark "glass" overlay drawn above the shell (the hole then shows the ground instead of removing the UI). Visually ~90% as good; the shake and the shards still sell it. Test on the live box before committing to the shell-clip design.

The same generator at 300 × 26 px, seeded at the ✕, with a hole big enough to swallow the whole row. Cracks, glass shards, then the row height collapses and the rows below slide up. 7. Decisions and open questions

#DecisionRationale
1A new one-shot event layer, not a 17th flair.Flairs are row-scoped, ambient, persistent, CSS-only. This is viewport-scoped, 4 s, then gone. What carries over is the discipline (aria-hidden, pointer-events none, transforms only, reduced-motion gate), not the mount.
2The hole is a real evenodd clip on the shell.A drawn hole on top of an intact UI reads as a sticker. Removing the UI is what makes it "cracked open". Fallback to a clipped dark overlay only if the shell clip repaints too expensively (§4 risk).
3Shards are glass, not UI copies.Pixel capture is out. Tinted polygons with a white edge highlight read as glass at any size and cost nothing.
4Seeded geometry from a single impact point.Reproducible frames, storyboard-able, screenshot-testable. Vary the impact point per run, not the seed.
5Fist on PR merged, eye on update available; cube parked.The fist is the celebration. The eye never leaves the screen and is the quieter egg, which suits a passive "something new is in here" moment; it also has no clip-release seam. The cube is on-brand for a later landing beat.
6Palette entries plus the two derived transitions; once per event identity, palette never limited, in-flight triggers dropped. No trigger file.§6.
7Build the row-scale version first.Same generator, 1/20th the surface, and a legitimate egg on Ctrl+click kill. Proves the crack look before the viewport version.
8No sound.Autoplay policy, shared offices, and the terminal is the user's focus.

Phase 2 (crack realism, dead-pixel lines, 12 s flight): see screen-break-crack-realism-studies.html.

Open

  • Shell clip repaint cost with two or more xterm canvases on screen (the §4 risk). Decides shell-clip vs overlay-clip.
  • Light theme inside-the-monitor ground: pure dark behind a light UI is strong; a warm grey may sit better. Check with the Light app toggle above.
  • Mobile: the palette exists on coarse pointers too. Run it at the same geometry or skip below 640 px? Leaning skip; the shards need room to fall.
  • Whether the cube variant should end by landing on the brand crumb (a second beat that reuses the existing detach-orbit-land sweep) instead of retreating.

Reading

B is the recommendation. It buys the four distinctions you actually use when skimming a diff — keyword, string, comment, function name — for a bundle cost that does not need a conversation, and it stays synchronous so a diff never renders twice.

The case against C is not mainly weight, it is duplication. The code lens is already a full VS Code sitting one tile away, and it is where you go when you want to read code properly. The review surface's job is what changed, not what this file means — and structure is carried by the wash and the gutter, not by token colour. Paying editor-grade highlighting to sit next to an actual editor is the expensive half of a distinction the layout already makes.

The case against A is thinner than it looks — flip the tint off and it is still perfectly readable. If the dependency budget is the binding constraint, A is a defensible ship, and B remains a drop-in later.

One thing to check before committing. Toggle the tint off and back on in light theme. Prism's default string green sits close enough to the add-wash green that on a light ground it reads as "highlighted because added" rather than "highlighted because string". If B is chosen, its light-theme string token wants re-picking against the wash — the same derivation problem the toggle-depth study hit with accentGreen at 2.7:1 on light.
